TreeSet & TreeMap
Sorted Order, Always.

Most problems that seem to need sorting actually need maintained sorted order — a subtle but critical distinction. TreeSet and TreeMap give you that in O(log n) per operation.

Red-Black Tree O(log n) ops Sorted Keys No Duplicates (TreeSet) Sliding Window Range Queries
01 — Core Insight

Why Sorted Order Matters

When you sort an array, you pay O(n log n) once and then iterate. But what if the array changes? Adding one element means re-sorting — expensive. TreeSet and TreeMap maintain sorted order continuously, paying only O(log n) per change.

The Core Insight: Use TreeSet/TreeMap when you need to repeatedly ask "what comes first or last in the current sorted order?" after insertions and deletions. Sorting once doesn't work when the data is a moving target.

Both are backed by a Red-Black Tree — a self-balancing binary search tree. Every insertion and deletion automatically rebalances the tree, keeping all operations at O(log n).

Gotcha: TreeSet and TreeMap throw NullPointerException if you try to add null. They need to compare elements, and you can't compare null. Always guard your inputs.

02 — TreeSet Deep Dive

TreeSet — Sorted Unique Values

TreeSet stores a sorted set of unique values. Think of it as a sorted array you can insert into and delete from in O(log n). The killer feature: navigation methods — finding the closest element to any target in O(log n).

Initialization

// Natural ascending order
TreeSet<Integer> set = new TreeSet<>();

// Descending order
TreeSet<Integer> desc = new TreeSet<>(Comparator.reverseOrder());

// From existing collection
TreeSet<Integer> fromList = new TreeSet<>(Arrays.asList(3, 1, 2));
// → {1, 2, 3}

// Custom comparator (sort strings by length)
TreeSet<String> byLen = new TreeSet<>(Comparator.comparingInt(String::length));

03 — TreeMap Deep Dive

TreeMap — Sorted Key-Value Pairs

TreeMap is TreeSet's sibling — it stores key-value pairs sorted by key. The killer use case: frequency maps in sliding windows. When you need to track duplicates AND maintain sorted order, TreeMap wins over TreeSet every time.

Rule of Thumb: If your window can contain duplicates, use TreeMap<Integer, Integer> (value → frequency) instead of TreeSet. TreeSet loses duplicate information; TreeMap preserves it.

Frequency Map Pattern

TreeMap<Integer, Integer> freq = new TreeMap<>();

// ADD element to window
int incoming = 5;
freq.put(incoming, freq.getOrDefault(incoming, 0) + 1);

// REMOVE element from window
int outgoing = 3;
freq.put(outgoing, freq.get(outgoing) - 1);
if (freq.get(outgoing) == 0) {
    freq.remove(outgoing);  // clean up zero-freq keys!
}

// GET max and min of current window — O(log n)
int max = freq.lastKey();
int min = freq.firstKey();

// Elegant alternative using merge()
freq.merge(incoming, 1, Integer::sum);  // add 1 or put 1 if absent
freq.merge(outgoing, -1, Integer::sum); // subtract 1
freq.values().removeIf(v -> v == 0);    // cleanup zeros

05 — The 4 Patterns

When to Reach for Each

Pattern 1 · Closest Element

Finding the Closest / Neighbor Value

Use floor() and ceiling() to find the nearest value to a target in O(log n). This beats sorting (O(n log n)) when you need multiple queries.

The insight: Any value closest to target is either the largest value ≤ target (floor) or the smallest value ≥ target (ceiling). Check both, pick the nearer one. Tie-break to the smaller.

// Closest number to target in a set of numbers
public int closestValue(int[] nums, int target) {
    TreeSet<Integer> set = new TreeSet<>();
    for (int n : nums) set.add(n);

    Integer lo = set.floor(target);    // largest ≤ target
    Integer hi = set.ceiling(target);  // smallest ≥ target

    if (lo == null) return hi;
    if (hi == null) return lo;

    // Equal distance → return smaller (lo)
    return (target - lo <= hi - target) ? lo : hi;
}
from sortedcontainers import SortedList

def closest_value(nums, target):
    sl = SortedList(nums)
    idx = sl.bisect_left(target)

    candidates = []
    if idx < len(sl): candidates.append(sl[idx])     # ceiling
    if idx > 0: candidates.append(sl[idx - 1])        # floor

    return min(candidates, key=lambda x: (abs(x - target), x))

Pattern 2 · Sliding Window + Duplicates

Sliding Window with Ordered Data

Use TreeMap when your sliding window needs the min or max at each step AND the window can contain duplicates. The frequency map trick — storing value → count — lets you safely add and remove elements.

Common mistake: Using TreeSet in a window that has duplicates. When you remove an outgoing element from TreeSet, you lose ALL copies of that value. Always use TreeMap with frequency counts when duplicates are possible.

// Sliding window max with TreeMap (handles duplicates)
public int[] maxSlidingWindow(int[] nums, int k) {
    TreeMap<Integer, Integer> map = new TreeMap<>();
    int[] res = new int[nums.length - k + 1];

    for (int i = 0; i < nums.length; i++) {
        // Add incoming
        map.put(nums[i], map.getOrDefault(nums[i], 0) + 1);

        // Remove outgoing (once window exceeds size k)
        if (i >= k) {
            int out = nums[i - k];
            map.put(out, map.get(out) - 1);
            if (map.get(out) == 0) map.remove(out);
        }

        // Record result once window is full
        if (i >= k - 1) res[i - k + 1] = map.lastKey();
    }
    return res;
}
from sortedcontainers import SortedDict

def max_sliding_window(nums, k):
    freq = SortedDict()
    res = []

    for i, n in enumerate(nums):
        freq[n] = freq.get(n, 0) + 1

        if i >= k:
            out = nums[i - k]
            freq[out] -= 1
            if freq[out] == 0: del freq[out]

        if i >= k - 1:
            res.append(freq.keys()[-1])  # lastKey = max

    return res

Pattern 3 · Range Queries

Counting / Querying Elements in a Range

subSet(lo, hi) returns a live view of elements in a range. Calling .size() on it gives you an O(log n) range count — no iteration needed.

// Count elements in range [lo, hi]
public int countInRange(int[] nums, int lo, int hi) {
    TreeSet<Integer> set = new TreeSet<>();
    for (int n : nums) set.add(n);

    return set.subSet(lo, true, hi, true).size();
}

// Check if any two nums are within value distance k
public boolean containsNearbyAlmostDuplicate(int[] nums, int k, long t) {
    TreeSet<Long> window = new TreeSet<>();
    for (int i = 0; i < nums.length; i++) {
        Long lo = window.ceiling((long) nums[i] - t);
        if (lo != null && lo <= (long) nums[i] + t) return true;
        window.add((long) nums[i]);
        if (window.size() > k) window.remove((long) nums[i - k]);
    }
    return false;
}
from sortedcontainers import SortedList

def count_in_range(nums, lo, hi):
    sl = SortedList(nums)
    left = sl.bisect_left(lo)
    right = sl.bisect_right(hi)
    return right - left

def contains_nearby_almost_duplicate(nums, k, t):
    window = SortedList()
    for i, n in enumerate(nums):
        idx = window.bisect_left(n - t)
        if idx < len(window) and window[idx] <= n + t:
            return True
        window.add(n)
        if len(window) > k:
            window.remove(nums[i - k])
    return False

Pattern 4 · Second Largest / K-th Element

K-th Smallest / Largest Element

TreeSet's sorted order makes finding the k-th element intuitive — poll from the appropriate end, or use pollLast() / pollFirst() repeatedly. For the second largest specifically: remove the largest, peek at what remains.

// Second largest (distinct values only)
public int secondLargest(int[] nums) {
    TreeSet<Integer> set = new TreeSet<>();
    for (int n : nums) set.add(n);
    if (set.size() < 2) return -1;
    set.pollLast();         // remove largest
    return set.last();     // second largest
}

// K-th smallest
public int kthSmallest(int[] nums, int k) {
    TreeSet<Integer> set = new TreeSet<>();
    for (int n : nums) set.add(n);
    for (int i = 0; i < k - 1; i++) set.pollFirst();
    return set.first();
}
from sortedcontainers import SortedList

def second_largest(nums):
    sl = SortedList(set(nums))  # deduplicate first
    if len(sl) < 2: return -1
    return sl[-2]              # second from end

def kth_smallest(nums, k):
    sl = SortedList(nums)
    return sl[k - 1]           # 0-indexed

06 — Deep Dives

Two Problems Worth Studying Carefully

LC 480 · Sliding Window Median Hard

Find the median of every window of size k in an array. Medians require both the lower and upper halves — two TreeMaps is the clean solution.

Key insight: Maintain two TreeMaps — lo for the lower half (max at top) and hi for the upper half (min at top). Always balance them so |lo.size() - hi.size()| ≤ 1. Median = average of both tops (even k) or top of larger half (odd k).

public double[] medianSlidingWindow(int[] nums, int k) {
    // lo = max-heap (descending), hi = min-heap (ascending)
    TreeMap<Integer,Integer> lo = new TreeMap<>(Collections.reverseOrder());
    TreeMap<Integer,Integer> hi = new TreeMap<>();
    double[] res = new double[nums.length - k + 1];

    for (int i = 0; i < nums.length; i++) {
        addTo(lo, nums[i]);
        addTo(hi, lo.firstKey());
        removeFrom(lo, hi.firstKey());  // rebalance

        if (hi.size() > lo.size()) {
            addTo(lo, hi.firstKey());
            removeFrom(hi, hi.firstKey());
        }

        if (i >= k - 1) {
            res[i - k + 1] = lo.size() == hi.size()
                ? ((double) lo.firstKey() + hi.firstKey()) / 2
                : lo.firstKey();
            removeFrom(nums[i - k + 1] <= lo.firstKey() ? lo : hi,
                       nums[i - k + 1]);
        }
    }
    return res;
}

private void addTo(TreeMap<Integer,Integer> m, int v) {
    m.put(v, m.getOrDefault(v, 0) + 1);
}
private void removeFrom(TreeMap<Integer,Integer> m, int v) {
    m.put(v, m.get(v) - 1);
    if (m.get(v) == 0) m.remove(v);
}
from sortedcontainers import SortedList

def median_sliding_window(nums, k):
    window = SortedList(nums[:k])
    res = []

    def get_median():
        if k % 2: return float(window[k // 2])
        return (window[k//2-1] + window[k//2]) / 2

    res.append(get_median())
    for i in range(k, len(nums)):
        window.add(nums[i])
        window.remove(nums[i - k])
        res.append(get_median())
    return res
LC 220 · Contains Duplicate III Hard

Return true if there are indices i ≠ j such that |i - j| ≤ k and |nums[i] - nums[j]| ≤ t. Sliding window + range query in one.

The elimination argument: Maintain a TreeSet window of size k. For each new element x, check if any element in the window falls in [x-t, x+t] using ceiling(x-t). If that ceiling exists and is ≤ x+t, a pair exists. We only need one call — ceiling gives the closest candidate above our lower bound.

public boolean containsNearbyAlmostDuplicate(int[] nums, int k, long t) {
    TreeSet<Long> window = new TreeSet<>();

    for (int i = 0; i < nums.length; i++) {
        long x = nums[i];

        // Is there any value in [x-t, x+t] already in the window?
        Long candidate = window.ceiling(x - t);
        if (candidate != null && candidate <= x + t) return true;

        window.add(x);
        if (window.size() > k) window.remove((long) nums[i - k]);
    }
    return false;
}
from sortedcontainers import SortedList

def contains_nearby_almost_duplicate(nums, k, t):

            return True

            window.remove(nums[i - k])
    return False
