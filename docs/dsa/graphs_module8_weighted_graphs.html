Weighted graphs — when BFS stops working

BFS is perfect only when every edge has the same cost. The moment one path costs 2 and another costs 7, “fewest edges” is no longer the same thing as “cheapest path.” That is exactly where Dijkstra enters the picture.

Recognition signal: shortest path is still the goal, but edges have weights like time, price, effort, risk, or distance. Unweighted shortest path → BFS. Weighted shortest path with non-negative weights → Dijkstra.

The queue changes

BFS uses FIFO order. Dijkstra uses a min-heap so the next node processed is always the cheapest-known frontier node.

The invariant

When a node is popped from the min-heap with its best known distance, that distance is final — provided all edge weights are non-negative.

Core template

Dijkstra with a min-heap 
// graph[node] = list of {neighbor, weight}
PriorityQueue<int[]> pq = new PriorityQueue<>((a,b) -> a[1] - b[1]);
Arrays.fill(dist, Integer.MAX_VALUE);
dist[src] = 0;
pq.add(new int[]{src, 0});

while (!pq.isEmpty()) {
    int[] cur = pq.poll();
    int node = cur[0], d = cur[1];
    if (d > dist[node]) continue;
    for (int[] edge : graph.get(node)) {
        int nei = edge[0], w = edge[1];
        int nd = d + w;
        if (nd < dist[nei]) {
            dist[nei] = nd;
            pq.add(new int[]{nei, nd});
        }
    }
}
import heapq

dist = [float('inf')] * n
dist[src] = 0
pq = [(0, src)]  # (distance, node)

while pq:
    d, node = heapq.heappop(pq)
    if d > dist[node]:
        continue
    for nei, w in graph[node]:
        nd = d + w
        if nd < dist[nei]:
            dist[nei] = nd
            heapq.heappush(pq, (nd, nei))

How to think about it

Dijkstra is a “best-so-far frontier” algorithm. The heap stores candidate paths. Each pop asks: “Among all unfinished routes, which one is currently cheapest?” That one is safe to finalize before the rest.

Common mistake: writing BFS because the prompt says “shortest path,” while missing that the edge costs are not equal. The word shortest does not automatically mean BFS. It only means BFS when all moves cost the same.

Still BFS

If every move costs exactly one, keep using BFS. Don’t bring a heap to an unweighted problem.

Not Dijkstra

If weights can be negative, Dijkstra’s guarantee breaks. That’s when Bellman-Ford or other tools enter the picture.
