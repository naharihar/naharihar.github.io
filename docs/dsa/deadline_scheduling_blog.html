Deadline Scheduling is really about claims on a timeline

Most interval problems look unrelated on the surface: meetings, room bookings, balloons, courses, jobs, calendars. Underneath, they all ask the same question: how should we manage competing claims on time?

01 — First Principle

Every scheduling problem starts with the same reframing

Ignore the story for a second. A meeting, a reservation, a course, and a taxi ride are all just intervals that want space on a shared timeline. Once you see that, the question becomes structural: are we choosing a subset, serving everything with enough resources, or maximizing value?

Scheduling gets easier the moment you stop thinking about tasks and start thinking about intervals competing for capacity.

The greedy heart of this family is simple: an interval that frees the timeline earlier usually preserves more future options. That is why end-time sorting shows up again and again. But not every variant is pure EDF. Some need a heap because many intervals are active at once, and some need dynamic programming because value matters more than count.

Why the earliest finish is often the safest choice

Imagine you have one hotel room and several booking requests. Which one should you confirm first if you want to keep the room as flexible as possible for later requests? Not the longest booking, and not the one that starts earliest. The best first choice is the booking that ends earliest.

Reusable mental model If accepting one interval leaves you with the most room for future intervals, it is usually a good greedy candidate. That is the intuition behind interval scheduling, pair chains, and several deadline variants.

02 — The Four Patterns

Once the timeline is clear, the family splits into four shapes

The key is not “is this a scheduling problem?” The key is “what is the objective?” That one choice tells you whether you should use a pointer-only greedy, a heap, or DP.

Pattern 1

Maximize Count

Choose the largest subset of non-overlapping intervals. Sort by end time, then keep what fits.

Pattern 2

Minimize Removals / Cut Points

Keep the schedule conflict-free with the smallest number of deletions or cuts. Often the complement of Pattern 1.

Minimize Resources

All intervals must be served, so the question becomes: how many rooms, machines, or calendars do we need?

Pattern 4

Maximize Value

When intervals have value or duration tradeoffs, pure greedy stops being enough. This is where heaps or DP enter.

Pattern 1 — Maximize Count

Question: out of all possible intervals, how many can I keep without overlap? Sort by end time and greedily accept an interval when its start is at or after the end of the last accepted one.

// Keep as many intervals as possible
intervals.sort((a, b) => a.end - b.end);
let lastEnd = -Infinity, kept = 0;
for (const iv of intervals) {
  if (iv.start >= lastEnd) {
    kept++;
    lastEnd = iv.end;
  }
}

Pattern 2 — Minimize Removals or Cut Points

This is usually just Pattern 1 with one extra sentence. If you know the maximum number you can keep, then removals = total - kept. Balloon arrows are a sibling of the same idea: an arrow is a cut point that serves all intervals overlapping that point.

Pattern 3 — Minimize Resources

Now you are not allowed to reject anything. That changes the question completely. Instead of selecting intervals, you process them in start-time order and use a min-heap to track which currently used resource frees up first.

Heap intuition The heap answers one question over and over: what is the earliest finishing active interval? If that one ends before the next interval starts, its room can be reused.

Pattern 4 — Maximize Value

Once weights or durations matter, “take the earliest finish” is not enough. Course Schedule III still starts with deadline order, but it needs a max-heap swap. Weighted job scheduling needs DP + binary search because taking one expensive interval might be better than taking several smaller ones.

03 — Recognition Skill

The three questions that classify almost every scheduling problem

1

Can I model each item as a claim on time?

If there is a start/end, arrival/deadline, or duration/deadline pair, you are probably in the scheduling family even if the statement never says “interval.”

2

Am I choosing a subset or serving everything?

If you may reject intervals, think greedy or weighted scheduling. If everything must be served, think resource counting and active-interval heaps.

3

Is the objective count, removals, resources, or value?

The objective decides the algorithm family: pointer greedy, complement reasoning, min-heap reuse, or DP + binary search.

05 — The Learning Path

Six problems to build real fluency

Do these in order. Each one adds exactly one new idea to your toolkit.

1

LC 435 — Non-overlapping Intervals

Pure end-time greedy. This is the template that makes the rest of the family feel coherent.

2

LC 452 — Minimum Arrows to Burst Balloons

Same structural idea, different framing. Great practice for recognizing when “minimum operations” is secretly interval grouping.

3

LC 253 — Meeting Rooms II

Your first active-interval heap. Everything must be served, so the problem becomes peak overlap.

4

LC 729 — My Calendar I

Dynamic scheduling rather than batch scheduling. Learn to check only the neighbors that could actually conflict.

5

LC 630 — Course Schedule III

Deadline order + max-heap replacement. This is the breakthrough problem where greedy becomes more subtle.

6

LC 1235 — Maximum Profit in Job Scheduling

The weighted version. Once this clicks, interval DP stops feeling like a memorized trick.

06 — The Mental Model

One sentence that ties the whole track together

Scheduling problems become easy when you identify what the timeline capacity is, what “conflict” means, and what objective you are optimizing against that capacity.

The fastest candidates in interviews are not magically recognizing fifty different problems. They are translating each new story into one of four scheduling shapes. Once you can do that, the algorithm follows almost mechanically.
