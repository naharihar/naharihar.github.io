01 —

Arrays

Arrays are the foundation of DSA. Java arrays are fixed-size and typed — once created you cannot resize them. They live on the heap and all elements are zero-initialized.

Key mental model: arr.length is a field, not a method — no parentheses. String uses .length() with (). 2D arrays are arrays of arrays: grid[row][col].
Declaration & initialization
1D array — all ways to create
core▶
// declare with size — default value is 0 for int, null for objects, false for boolean
int[] arr = new int[5];           // [0, 0, 0, 0, 0]
boolean[] seen = new boolean[10]; // [false, false, ...]
String[] words = new String[4];   // [null, null, null, null]

// declare with inline values
int[] arr = {1, 2, 3, 4, 5};

// fill entire array with a specific value
Arrays.fill(arr, -1);    // [-1, -1, -1, -1, -1]
Arrays.fill(arr, 0, 3, 9); // fill indices [0,3) with 9

// length — field, no parentheses!
int n = arr.length;  // not arr.length()
# list with default value
arr = [0] * 5           # [0, 0, 0, 0, 0]
seen = [False] * 10

# inline values
arr = [1, 2, 3, 4, 5]

# length
n = len(arr)
For DSA: prefer int[] over Integer[] for performance. Use Integer[] only when you need null checks or Collections methods.

Arrays.sort — primitives, objects, and custom order
dsa▶
// sort int[] ascending — in-place, O(n log n)

// sort only a subrange [from, to)

Arrays.sort(boxed, Collections.reverseOrder());

// sort 2D array by first column (interval problems)
int[][] intervals = {{3,6},{1,4},{2,5}};
Arrays.sort(intervals, (a, b) -> Integer.compare(a[0], b[0]));
// result: [[1,4],[2,5],[3,6]]

// sort by multiple criteria: first by start, then by end desc
Arrays.sort(intervals, (a, b) ->
    a[0] != b[0] ? Integer.compare(a[0], b[0]) : Integer.compare(b[1], a[1]));

intervals.sort(key=lambda x: (x[0], -x[1]))  # multi-key

Strings & StringBuilder

Strings in Java are immutable — every operation like +, substring, or replace creates a brand new String object. This matters in loops: building a string by concatenation in a loop is O(n²). Use StringBuilder for any in-loop string building.

The classic O(n²) trap: String result = ""; for (...) result += c; — each += copies the entire string. Always use StringBuilder in loops.

ArrayList & LinkedList

ArrayList is your go-to dynamic array — O(1) get/set, O(1) amortized add-to-end, O(n) insert/remove from middle. It's backed by an array that doubles when capacity is exceeded. Use it when you need index access and mostly append to end.

DSA usage: ArrayList<Integer> for dynamic result lists, ArrayList<List<Integer>> for 2D results like subsets/permutations, ArrayList<int[]> for storing coordinate pairs.

HashMap, LinkedHashMap & TreeMap

HashMap gives you O(1) average put/get/remove. It's the single most used collection in DSA — frequency counts, memoization, grouping, caching. Know its methods cold.

Three map flavors: HashMap (O(1), unordered) → LinkedHashMap (O(1), insertion order) → TreeMap (O(log n), sorted keys). Pick based on whether you need ordering.

HashSet & TreeSet

HashSet gives O(1) contains — the fastest way to answer "have I seen this before?" Use it for deduplication, cycle detection, and visited tracking in BFS/DFS.

When to use Set over Map: If you only need membership (yes/no) and not a count or associated value, use a Set. It's cleaner and signals intent clearly.

ArrayDeque — Stack & Queue

ArrayDeque is a double-ended queue backed by a resizable array. Use it as both a Stack (LIFO) and a Queue (FIFO). Never use the legacy Stack class — it's synchronized and slow.

Common mistake: push/pop give you a Stack (LIFO). addLast/removeFirst give you a Queue (FIFO). Mixing them gives wrong BFS/DFS behavior.
Stack & Queue patterns
As a Stack — DFS, parentheses, monotonic
dsa▶
Deque<Integer> stack = new ArrayDeque<>();

stack.push(1);     // addFirst — puts at HEAD
stack.push(2);
stack.push(3);     // stack: [3, 2, 1] (head → tail)

stack.peek();      // 3 — see top without removing (null if empty)
stack.pop();       // 3 — remove top (throws if empty)
stack.isEmpty();   // false

// Iterative DFS template
Deque<Integer> stack = new ArrayDeque<>();
stack.push(start);
while (!stack.isEmpty()) {
    int node = stack.pop();
    // process node...
    for (int neighbor : graph[node]) {
        if (!visited.contains(neighbor)) {
            visited.add(neighbor);
            stack.push(neighbor);
        }
    }
}
stack = []
stack.append(1)   # push
stack[-1]         # peek
stack.pop()       # pop

# DFS

    node = stack.pop()

As a Queue — BFS, level-order
dsa▶
Deque<Integer> queue = new ArrayDeque<>();

queue.addLast(1);    // enqueue — adds to TAIL
queue.addLast(2);
queue.addLast(3);    // queue: [1, 2, 3] (head → tail)

queue.peekFirst();   // 1 — see front (null if empty)

// BFS template — grid problems
Deque<int[]> queue = new ArrayDeque<>();
queue.addLast(new int[]{startRow, startCol});
boolean[][] visited = new boolean[rows][cols];
visited[startRow][startCol] = true;

int[][] dirs = {{0,1},{0,-1},{1,0},{-1,0}};
while (!queue.isEmpty()) {
    int[] curr = queue.removeFirst();
    int r = curr[0], c = curr[1];
    for (int[] d : dirs) {
        int nr = r + d[0], nc = c + d[1];
        if (nr >= 0 && nr < rows && nc >= 0 && nc < cols
                && !visited[nr][nc]) {
            visited[nr][nc] = true;
            queue.addLast(new int[]{nr, nc});
        }
    }
}

PriorityQueue — Heap

PriorityQueue is a min-heap by default — poll() always returns the smallest element. It's your go-to for top-K problems, Dijkstra's algorithm, and any "always process the most urgent item" pattern.

Default = min-heap. For a max-heap: new PriorityQueue<>(Collections.reverseOrder()). For custom objects: pass a Comparator. PriorityQueue does NOT support O(1) random access — only peek/poll the top.

// Logic: maintain K largest seen. If new element > min of heap, swap.

}

    (a, b) -> freq.get(a) - freq.get(b)  // min-heap by frequency

5 Bugs That Will Cost You

These are the exact mistakes that appeared in your self-assessment — and the ones that come up most in real problems. Learn them once and never lose points to syntax again.

Bug 1 — Backtracking reference trap
res.add(path) adds a reference to the mutable list. All entries in res end up empty when DFS unwinds.
// WRONG — all entries in res point to the same list
res.add(path);

// CORRECT — snapshot the current state
res.add(new ArrayList<>(path));
# WRONG
res.append(path)
# CORRECT
res.append(path[:])
Bug 2 — Integer overflow in Comparator
(a - b) as a comparator overflows when a = Integer.MIN_VALUE and b = 1, producing a huge positive number and wrong sort order.
// WRONG — silent overflow
Arrays.sort(arr, (a, b) -> a - b);

// CORRECT
Arrays.sort(arr, (a, b) -> Integer.compare(a, b));
# Python ints don't overflow — subtraction is safe
# but use key= style for clarity
arr.sort(key=lambda x: x)
Bug 3 — String comparison with ==
== checks reference identity in Java. Two String objects with the same characters are not == unless they're the same interned object.
// WRONG
if (s1 == s2) { ... }

// CORRECT
if (s1.equals(s2)) { ... }
if (s1.equalsIgnoreCase(s2)) { ... }
# Python == works correctly for strings
if s1 == s2: ...
Bug 4 — Missing recursion base case
Forgetting one of the base cases causes infinite recursion, eventually crashing with StackOverflowError.
// WRONG — missing n == 1 case causes infinite recursion
int fib(int n) {
    if (n == 0) return 0;
    return fib(n-1) + fib(n-2);
}

// CORRECT
int fib(int n) {
    if (n == 0) return 0;
    if (n == 1) return 1;
    return fib(n-1) + fib(n-2);
}
def fib(n):
    if n == 0: return 0
    if n == 1: return 1
    return fib(n-1) + fib(n-2)
Bug 5 — ArrayList.remove(int) vs remove(Object)
list.remove(1) removes the element at index 1. list.remove(Integer.valueOf(1)) removes the value 1. Passing a plain int always removes by index.
List<Integer> list = new ArrayList<>(Arrays.asList(10, 20, 30));

list.remove(1);                     // removes INDEX 1 → [10, 30]
list.remove(Integer.valueOf(10));    // removes VALUE 10 → [30]
lst = [10, 20, 30]
lst.pop(1)       # by index: [10, 30]
lst.remove(10)   # by value: [30]

Real DSA Patterns — Collections in Action

This is where syntax becomes skill. Each pattern below shows exactly which collection to reach for, why, and how int[] and wrapper types interact in real problem code.

Pattern 1 — Two Sum & index lookup

Store value → index in a HashMap. For each number, check if its complement already exists. This is the canonical O(n) vs O(n²) upgrade — raw array would require a nested loop.

Why HashMap wins: HashMap.containsKey() is O(1). Scanning an int[] for the complement is O(n). One lookup per element → O(n) total.
Two Sum — HashMap<Integer, Integer> for value → index
HashMap▶
// Problem: find two indices where nums[i] + nums[j] == target
public int[] twoSum(int[] nums, int target) {
    // int[] as input — primitives fine here, it's just an array
    Map<Integer, Integer> seen = new HashMap<>();

    for (int i = 0; i < nums.length; i++) {
        int complement = target - nums[i];

        if (seen.containsKey(complement)) {
            // return int[] — primitives fine as return type
            return new int[]{seen.get(complement), i};
        }
        seen.put(nums[i], i);   // autoboxing: int → Integer for map key
    }
    return new int[]{-1, -1};
}

// int[] input: nums = [2, 7, 11, 15], target = 9
// Step i=0: complement=7, not in map. map: {2→0}
// Step i=1: complement=2, FOUND at index 0 → return [0, 1]
def two_sum(nums, target):
    seen = {}
    for i, n in enumerate(nums):
        complement = target - n
        if complement in seen:
            return [seen[complement], i]
        seen[n] = i
    return [-1, -1]
int[] is used for input and return type — primitives work fine. The HashMap must be Map<Integer, Integer> — wrapper types required for generics.

Pattern 2 — Sliding Window with frequency map

Use a HashMap or int[26] array to track character frequencies inside a window. The int[26] trick works when the alphabet is fixed (lowercase a-z) and is faster than a HashMap because there's no boxing overhead.

int[26] vs HashMap: When the key space is small and fixed (26 letters, 10 digits, 256 ASCII), a primitive int[] indexed by character value beats HashMap — O(1) with zero allocation overhead.
Longest substring without repeating — HashSet for "seen"
HashSet▶
// Problem: find length of longest substring with all unique chars
public int lengthOfLongestSubstring(String s) {
    Set<Character> window = new HashSet<>(); // Character, not char
    int left = 0, maxLen = 0;

    for (int right = 0; right < s.length(); right++) {
        char c = s.charAt(right);

        // shrink window from left until c is no longer a duplicate
        while (window.contains(c)) {
            window.remove(s.charAt(left));  // autoboxed char → Character
            left++;
        }
        window.add(c);
        maxLen = Math.max(maxLen, right - left + 1);
    }
    return maxLen;
}
// s = "abcabcbb" → 3 ("abc")
def length_of_longest_substring(s):
    window = set()
    left = maxLen = 0
    for right, c in enumerate(s):
        while c in window:
            window.discard(s[left])
            left += 1
        window.add(c)
        maxLen = max(maxLen, right - left + 1)
    return maxLen
Anagram check — int[26] array beats HashMap here
int[26]▶
// Problem: given s and p, find all start indices where p's anagram appears in s
public List<Integer> findAnagrams(String s, String p) {
    List<Integer> result = new ArrayList<>(); // List needs Integer, not int

    // int[26] — primitive array indexed by (char - 'a'). Faster than HashMap.
    int[] pCount = new int[26];
    int[] wCount = new int[26];

    for (char c : p.toCharArray()) pCount[c - 'a']++;

    for (int i = 0; i < s.length(); i++) {
        wCount[s.charAt(i) - 'a']++;         // add right char

        if (i >= p.length()) {
            wCount[s.charAt(i - p.length()) - 'a']--;  // remove left char
        }
        if (Arrays.equals(pCount, wCount)) {
            result.add(i - p.length() + 1);  // autoboxing: int → Integer
        }
    }
    return result;
}
// s="cbaebabacd", p="abc" → [0, 6]
// int[26] comparison with Arrays.equals() is O(26) = O(1) effectively
from collections import Counter
def find_anagrams(s, p):
    result = []
    pCount = Counter(p)
    wCount = Counter(s[:len(p)])
    if wCount == pCount: result.append(0)
    for i in range(len(p), len(s)):
        wCount[s[i]] += 1
        wCount[s[i - len(p)]] -= 1
        if wCount[s[i - len(p)]] == 0:
            del wCount[s[i - len(p)]]
        if wCount == pCount:
            result.append(i - len(p) + 1)
    return result
int[26] trick: c - 'a' maps 'a'→0, 'b'→1 ... 'z'→25. Use this any time your key space is small letters or digits — no boxing, no hashing, just array indexing.

Pattern 3 — BFS shortest path with int[] in queue

BFS on a grid needs a queue storing coordinates as int[]. The queue is Deque<int[]> — the int[] is an object so it can go into a collection, but its internal values are primitives for speed.

01 Matrix — BFS with Deque<int[]> storing {row, col, dist}
Deque<int[]>▶
// Problem: for each cell, find distance to nearest 0
public int[][] updateMatrix(int[][] mat) {
    int rows = mat.length, cols = mat[0].length;
    int[][] dist = new int[rows][cols];   // result grid — primitives
    boolean[][] visited = new boolean[rows][cols];

    // int[] as element type in Deque — {row, col}
    Deque<int[]> queue = new ArrayDeque<>();

    // multi-source BFS: seed all 0-cells at distance 0
    for (int r = 0; r < rows; r++) {
        for (int c = 0; c < cols; c++) {
            if (mat[r][c] == 0) {
                visited[r][c] = true;
                queue.addLast(new int[]{r, c});  // int[] stored as object
            }
        }
    }

    int[][] dirs = {{0,1},{0,-1},{1,0},{-1,0}};
    while (!queue.isEmpty()) {
        int[] curr = queue.removeFirst();   // unpack int[] back to primitives
        int r = curr[0], c = curr[1];

        for (int[] d : dirs) {
            int nr = r + d[0], nc = c + d[1];
            if (nr >= 0 && nr < rows && nc >= 0 && nc < cols
                    && !visited[nr][nc]) {
                visited[nr][nc] = true;
                dist[nr][nc] = dist[r][c] + 1;  // primitive arithmetic
                queue.addLast(new int[]{nr, nc});
            }
        }
    }
    return dist;
}
// Deque<int[]> — int[] is the object in the collection
// The values inside int[] (r, c) are primitives — fast access
from collections import deque
def update_matrix(mat):
    rows, cols = len(mat), len(mat[0])
    dist = [[float('inf')]*cols for _ in range(rows)]
    q = deque()
    for r in range(rows):
        for c in range(cols):
            if mat[r][c] == 0:
                dist[r][c] = 0
                q.append((r, c))
    for r, c in q:
        for dr, dc in [(0,1),(0,-1),(1,0),(-1,0)]:
            nr, nc = r+dr, c+dc
            if 0 <= nr < rows and 0 <= nc < cols:
                if dist[nr][nc] > dist[r][c] + 1:
                    dist[nr][nc] = dist[r][c] + 1
                    q.append((nr, nc))
    return dist
Pattern: new int[]{r, c} packages two primitives as a single object for the queue. When you pull it out, unpack immediately: int r = curr[0], c = curr[1]. This is standard Java grid BFS.

Pattern 4 — DFS / Backtracking building List<List<Integer>>

Backtracking builds results in a List<List<Integer>>. The path is a mutable List<Integer> — must use Integer not int. The snapshot rule (new ArrayList<>(path)) is critical.

Subsets — DFS with List<Integer> path, List<List<Integer>> result
ArrayList▶
// Problem: return all subsets of nums
public List<List<Integer>> subsets(int[] nums) {
    // int[] input — fine as array
    // result must be List<List<Integer>> — no primitives in generics
    List<List<Integer>> result = new ArrayList<>();
    dfs(nums, 0, new ArrayList<>(), result);
    return result;
}

private void dfs(int[] nums, int start,
                  List<Integer> path,
                  List<List<Integer>> result) {

    result.add(new ArrayList<>(path));  // SNAPSHOT — not result.add(path)!

    for (int i = start; i < nums.length; i++) {
        path.add(nums[i]);          // autoboxing: int nums[i] → Integer
        dfs(nums, i + 1, path, result);
        path.remove(path.size() - 1); // remove by INDEX (not value!)
    }
}
// nums=[1,2,3] → [[], [1], [1,2], [1,2,3], [1,3], [2], [2,3], [3]]
//
// path.remove(path.size()-1) removes last element by index
// Do NOT write path.remove(nums[i]) — that removes by value (wrong!)
def subsets(nums):
    result = []
    def dfs(start, path):
        result.append(path[:])  # snapshot with slice
        for i in range(start, len(nums)):
            path.append(nums[i])
            dfs(i + 1, path)
            path.pop()
    dfs(0, [])
    return result
Combination Sum — backtracking with duplicate skip
ArrayList▶
// Problem: find all combinations that sum to target (can reuse elements)
public List<List<Integer>> combinationSum(int[] candidates, int target) {
    List<List<Integer>> result = new ArrayList<>();
    Arrays.sort(candidates);  // sort int[] so we can prune early
    dfs(candidates, target, 0, new ArrayList<>(), result);
    return result;
}

private void dfs(int[] cands, int remain, int start,
                  List<Integer> path,
                  List<List<Integer>> result) {
    if (remain == 0) {
        result.add(new ArrayList<>(path));  // snapshot!
        return;
    }
    for (int i = start; i < cands.length; i++) {
        if (cands[i] > remain) break;  // pruning — sorted so rest will also exceed
        path.add(cands[i]);              // int autoboxed → Integer
        dfs(cands, remain - cands[i], i, path, result);  // i not i+1: can reuse
        path.remove(path.size() - 1);
    }
}
// candidates=[2,3,6,7], target=7 → [[2,2,3],[7]]
def combination_sum(candidates, target):
    candidates.sort()
    result = []
    def dfs(remain, start, path):
        if remain == 0:
            result.append(path[:])
            return
        for i in range(start, len(candidates)):
            if candidates[i] > remain: break
            path.append(candidates[i])
            dfs(remain - candidates[i], i, path)
            path.pop()
    dfs(target, 0, [])
    return result
sort() on int[] runs before DFS — enables the if (cands[i] > remain) break pruning. Without sorting you can't prune and must check all branches.

Pattern 5 — Heap with int[] pairs for weighted problems

Dijkstra's and similar weighted graph problems store {distance, node} as int[] in the PriorityQueue. The Comparator sorts on index [0] (the weight). This avoids creating a custom class just to hold two integers.

Dijkstra shortest path — PriorityQueue<int[]> with {dist, node}
PriorityQueue<int[]>▶
// Problem: single source shortest path — weighted graph
public int[] dijkstra(List<List<int[]>> graph, int src) {
    int n = graph.size();
    int[] dist = new int[n];          // int[] result — primitives
    Arrays.fill(dist, Integer.MAX_VALUE);
    dist[src] = 0;

    // min-heap of {distance, node} — int[] as element, sorted by dist
    PriorityQueue<int[]> pq = new PriorityQueue<>(
        (a, b) -> Integer.compare(a[0], b[0])  // sort by distance
    );
    pq.offer(new int[]{0, src});  // {dist=0, node=src}

    while (!pq.isEmpty()) {
        int[] curr = pq.poll();
        int d = curr[0], u = curr[1];

        if (d > dist[u]) continue;   // stale entry — skip

        for (int[] edge : graph.get(u)) {
            int v = edge[0], w = edge[1];  // neighbor, weight
            if (dist[u] + w < dist[v]) {
                dist[v] = dist[u] + w;
                pq.offer(new int[]{dist[v], v});
            }
        }
    }
    return dist;
}
// graph is List<List<int[]>> — adjacency list where each int[] = {neighbor, weight}
// PriorityQueue<int[]> — int[] is object in heap, values inside are primitives
import heapq
def dijkstra(graph, src):
    n = len(graph)
    dist = [float('inf')] * n
    dist[src] = 0
    heap = [(0, src)]
    while heap:
        d, u = heapq.heappop(heap)
        if d > dist[u]: continue
        for v, w in graph[u]:
            if dist[u] + w < dist[v]:
                dist[v] = dist[u] + w
                heapq.heappush(heap, (dist[v], v))
    return dist
int[] in PriorityQueue is the standard Java pattern for Dijkstra. The alternative is a custom class or record — int[] is faster to write in interviews. Always sort by index [0] which holds the priority.

Pattern 6 — Dynamic Programming with int[] and int[][]

DP tables are almost always primitive int[] or int[][] — never ArrayList or Integer[]. Random access is the whole point, and primitives give maximum speed with zero boxing.

Coin Change — int[] dp table, bottom-up
int[] DP▶
// Problem: fewest coins to make amount. coins=[1,5,10], amount=18 → 4
public int coinChange(int[] coins, int amount) {
    // int[] dp — primitive, size amount+1, all initialized to amount+1 (infinity)
    int[] dp = new int[amount + 1];
    Arrays.fill(dp, amount + 1);  // fill with "impossible" sentinel
    dp[0] = 0;                    // base case: 0 coins to make amount 0

    for (int i = 1; i <= amount; i++) {
        for (int coin : coins) {
            if (coin <= i) {
                dp[i] = Math.min(dp[i], dp[i - coin] + 1);
            }
        }
    }
    return dp[amount] > amount ? -1 : dp[amount];
}
// dp[0]=0, dp[1]=1, dp[5]=1, dp[10]=1, dp[18]=4 (10+5+1+1+1... → 10+5+1+1+1=5? no: 10+5+3*1=4)
// int[] — direct index access O(1), no boxing, exactly right here
def coin_change(coins, amount):
    dp = [amount + 1] * (amount + 1)
    dp[0] = 0
    for i in range(1, amount + 1):
        for coin in coins:
            if coin <= i:
                dp[i] = min(dp[i], dp[i - coin] + 1)
    return dp[amount] if dp[amount] <= amount else -1
Longest Common Subsequence — int[][] 2D DP
int[][] DP▶
// Problem: length of longest common subsequence of two strings
public int longestCommonSubsequence(String text1, String text2) {
    int m = text1.length(), n = text2.length();

    // int[][] dp — 2D primitive table, (m+1) x (n+1)
    int[][] dp = new int[m + 1][n + 1]; // auto-initialized to 0

    for (int i = 1; i <= m; i++) {
        for (int j = 1; j <= n; j++) {
            if (text1.charAt(i-1) == text2.charAt(j-1)) {
                dp[i][j] = dp[i-1][j-1] + 1;   // chars match
            } else {
                dp[i][j] = Math.max(dp[i-1][j], dp[i][j-1]); // take best
            }
        }
    }
    return dp[m][n];
}
// text1="abcde", text2="ace" → 3 ("ace")
// int[][] — 2D table, each cell O(1) access. Total: O(m*n) time & space
def longest_common_subsequence(text1, text2):
    m, n = len(text1), len(text2)
    dp = [[0]*(n+1) for _ in range(m+1)]
    for i in range(1, m+1):
        for j in range(1, n+1):
            if text1[i-1] == text2[j-1]:
                dp[i][j] = dp[i-1][j-1] + 1
            else:
                dp[i][j] = max(dp[i-1][j], dp[i][j-1])
    return dp[m][n]
2D DP tables are always int[][] — never ArrayList<ArrayList<Integer>>. Direct index access dp[i][j] is the whole point. auto-initialized to 0 saves a fill() call for base cases.

Pattern 7 — Monotonic Stack with ArrayDeque<Integer>

The monotonic stack keeps elements in sorted order — as you push, you pop anything that violates the invariant. Used for "next greater element", histogram areas, and temperature spans.

Daily Temperatures — monotonic stack of indices
Deque<Integer>▶
// Problem: for each day, how many days until a warmer temperature?
public int[] dailyTemperatures(int[] temps) {
    int[] answer = new int[temps.length];   // int[] result

    // stack stores INDICES (Integer), not temperatures
    Deque<Integer> stack = new ArrayDeque<>(); // Integer, not int

    for (int i = 0; i < temps.length; i++) {
        // pop all indices whose temperature is less than current
        while (!stack.isEmpty() && temps[stack.peek()] < temps[i]) {
            int prevIdx = stack.pop();           // unboxing Integer → int
            answer[prevIdx] = i - prevIdx;
        }
        stack.push(i);  // push current index (autoboxed int → Integer)
    }
    return answer;
}
// temps=[73,74,75,71,69,72,76,73]
// answer=[1, 1, 4, 2, 1, 1, 0, 0]
// Stack stores Integer (indices), result array stores int (days)
def daily_temperatures(temps):
    answer = [0] * len(temps)
    stack = []  # stores indices
    for i, t in enumerate(temps):
        while stack and temps[stack[-1]] < t:
            prev = stack.pop()
            answer[prev] = i - prev
        stack.append(i)
    return answer
Stack stores indices (Integer in Deque) not values. When you pop, you compute i - prevIdx using both as primitives. This is the standard monotonic stack structure.

Build graph + topological sort (BFS / Kahn's algorithm)

// Problem: course schedule — can you finish all courses given prerequisites?
public boolean canFinish(int numCourses, int[][] prerequisites) {
    // adjacency list — List<List<Integer>> (Integer, not int)
    List<List<Integer>> graph = new ArrayList<>();
    int[] inDegree = new int[numCourses];    // int[] — counts, primitive fine

    for (int i = 0; i < numCourses; i++)
        graph.add(new ArrayList<>());

    // build graph from int[][] prerequisites
    for (int[] pre : prerequisites) {
        graph.get(pre[1]).add(pre[0]);  // autoboxing int → Integer
        inDegree[pre[0]]++;
    }

    // BFS queue — Integer nodes with in-degree 0
    Deque<Integer> queue = new ArrayDeque<>();
    for (int i = 0; i < numCourses; i++)
        if (inDegree[i] == 0) queue.addLast(i);  // autoboxing

    int processed = 0;
    while (!queue.isEmpty()) {
        int node = queue.removeFirst();  // unboxing Integer → int
        processed++;
        for (int neighbor : graph.get(node)) {  // unboxing in for-each
            if (--inDegree[neighbor] == 0)
                queue.addLast(neighbor);
        }
    }
    return processed == numCourses;
}
// prerequisites=[[1,0],[2,1]] → true (0→1→2, no cycle)
from collections import defaultdict, deque
def can_finish(numCourses, prerequisites):
    graph = defaultdict(list)
    in_degree = [0] * numCourses
    for a, b in prerequisites:
        graph[b].append(a)
        in_degree[a] += 1
    q = deque(i for i in range(numCourses) if in_degree[i] == 0)
    processed = 0
    for node in q:
        processed += 1
        for nb in graph[node]:
            in_degree[nb] -= 1
            if in_degree[nb] == 0:
                q.append(nb)
    return processed == numCourses
inDegree is int[] — primitive array indexed by node. The graph is List<List<Integer>> — needs Integer for the inner list. Both live in the same function, which is normal.

The one sentence rule: Use int[] when size is fixed and you need index access. Use Integer (in a collection) when you need dynamic sizing, insertion, or removal. When you need both in one structure — like {dist, node} in a heap — use int[] as the element type so the pair becomes an object the collection can hold.
