Chapter 1 of 6

DFS is great.
But it has one fatal flaw.

You now know DFS well. It explores deeply, backtracks, and finds all reachable nodes. It's the right tool for connectivity, cycles, and component counting.

But here's the question DFS cannot answer correctly:

"What is the shortest path from node A to node B?"

Let's prove this with a tiny example. DFS from node 0 to node 3:

DFS FINDS THIS PATH (4 hops)
0 → 1 → 2 → 3 (went deep first)
THE ACTUAL SHORTEST (1 hop)
0 → 3 (direct edge exists!)

DFS doesn't know or care about shortest paths — it just goes deep. It might stumble onto the shortest path by luck, or it might find a path 10 hops longer. You cannot trust DFS for shortest path.

Why DFS fails here: DFS commits to one direction immediately and goes as far as possible. By the time it considers the direct edge 0→3, it's already deep in the 0→1→2→3 path. DFS is blind to the fact that a closer route exists.
A DIFFERENT STRATEGY
Chapter 2 of 6

Think of a ripple in water.

Drop a stone in a pond. Ripples spread outward in perfect circles — everything at distance 1 gets wet before anything at distance 2. Everything at distance 2 before distance 3. The wave is perfectly fair.

BFS works the same way. It explores all nodes at distance 1 before any at distance 2. All at distance 2 before any at distance 3. This layer-by-layer expansion is the entire reason BFS guarantees shortest paths.

BFS EXPANDS LEVEL BY LEVEL — LIKE RIPPLES
Press the button to animate the BFS ripple
The guarantee: When BFS first reaches a node, it's guaranteed to be via the shortest path. Why? Because BFS processes nodes in order of distance. If there were a shorter path, BFS would have found it already at an earlier level — but there's nothing earlier left to process. The first time = the shortest time.
THE KEY DIFFERENCE — THE QUEUE
Chapter 3 of 6

One data structure change.
Everything changes.

Here's the beautiful thing: BFS and DFS are almost identical code. The only structural difference is what data structure holds the nodes to visit next.

DFS — uses a STACK

A stack is LIFO — Last In, First Out.

  • Push neighbors onto stack
  • Pop the most recently added node
  • Goes deep before wide
  • Like a pile of plates
Push: [1,2] → Pop: 2 → deep
BFS — uses a QUEUE

A queue is FIFO — First In, First Out.

  • Enqueue neighbors
  • Dequeue the oldest node
  • Goes wide before deep
  • Like a line at a shop
Enqueue: [1,2] → Dequeue: 1 → wide

That's it. Swap the stack for a queue and DFS becomes BFS. The queue enforces the ripple order — nodes entered first are processed first, which means closer nodes always come before farther ones.

Stack = depth first. Queue = breadth first. This is not a coincidence — it's the definition. The data structure is the algorithm.
THE CODE
Chapter 4 of 6

The BFS template.
Learn it once, use it forever.

Compare this side by side with DFS. Spot the differences — there are only two: deque instead of recursion, and enqueue at discovery time, not visit time.

bfs.pyPython
from collections import deque

def bfs(graph, start):
    visited = {start}          # mark BEFORE enqueuing, not after dequeuing
    queue = deque([start])     # deque = efficient queue (O(1) popleft)
    order = []

    while queue:
        node = queue.popleft()   # FIFO: take from the FRONT
        order.append(node)

        for neighbor in graph[node]:
            if neighbor not in visited:
                visited.add(neighbor)       # mark when enqueuing
                queue.append(neighbor)      # add to BACK of queue

    return order   # nodes in BFS (shortest-path) order
BFS.javaJava
List<Integer> bfs(List<Integer>[] graph, int start) {
    boolean[] visited = new boolean[graph.length];
    Queue<Integer> queue = new LinkedList<>();
    List<Integer> order = new ArrayList<>();

    visited[start] = true;   // mark BEFORE enqueuing
    queue.add(start);

    while (!queue.isEmpty()) {
        int node = queue.poll();   // poll() = dequeue from front (FIFO)
        order.add(node);

        for (int neighbor : graph[node]) {
            if (!visited[neighbor]) {
                visited[neighbor] = true;  // mark when enqueuing
                queue.add(neighbor);
            }
        }
    }
    return order;
}
Critical: mark visited when enqueuing, not dequeuing. If you mark on dequeue, the same node can be added to the queue multiple times before it's processed, causing duplicated work (or incorrect distance counts). Always mark the moment you enqueue.

BFS for shortest path distance

To find actual distances, carry the distance alongside each node. When the target is first dequeued, that distance is guaranteed to be the shortest.

bfs_shortest.pyPython — Shortest Path Distance
from collections import deque

def shortest_path(graph, start, target):
    if start == target: return 0
    visited = {start}
    queue = deque([(start, 0)])   # (node, distance_from_start)

    while queue:
        node, dist = queue.popleft()
        for neighbor in graph[node]:
            if neighbor == target:
                return dist + 1   # ✓ first time = shortest path
            if neighbor not in visited:
                visited.add(neighbor)
                queue.append((neighbor, dist + 1))

    return -1   # target unreachable
BFSShortest.javaJava — Shortest Path Distance
int shortestPath(List<Integer>[] graph, int start, int target) {
    if (start == target) return 0;
    boolean[] visited = new boolean[graph.length];
    Queue<int[]> queue = new ArrayDeque<>();
    visited[start] = true;
    queue.add(new int[] {start, 0});

    while (!queue.isEmpty()) {
        int[] cur = queue.poll();
        int node = cur[0], dist = cur[1];
        for (int neighbor : graph[node]) {
            if (neighbor == target) return dist + 1;
            if (!visited[neighbor]) {
                visited[neighbor] = true;
                queue.add(new int[] {neighbor, dist + 1});
            }
        }
    }
    return -1;
}
