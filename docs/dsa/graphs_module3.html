FROM MAZE TO GRAPH
Chapter 2 of 6

The maze is a graph.
Every cell is a node.

Here's the key insight that connects what you just did to graph algorithms: a maze is just a graph in disguise. Every open cell is a node. Every two adjacent open cells share an edge. The walls just mean "no edge here."

So solving a maze and doing DFS on a graph are the same problem. The maze just makes the structure visual.

MAZE VIEW
SAME THING AS GRAPH

Now here's the one crucial difference between a maze and a graph: in a graph, you can revisit nodes. There are no one-way corridors. If you don't track where you've been, you'll loop forever.

The visited set — why it's non-negotiable: Without tracking visited nodes, DFS on a graph with a cycle will revisit the same node, recurse into it again, revisit its neighbor, recurse again… forever. Every graph DFS needs a visited set. No exceptions.
THE THREE RULES OF DFS
Chapter 3 of 6

DFS is just three rules.

Before we see any code, let's distill what you observed in the maze into three simple rules. Every DFS implementation — recursive or iterative, on any graph — follows exactly these rules:

1
Visit the current node. Mark it as seen.

Add it to your visited set immediately. This prevents re-processing.

2
For each unvisited neighbor, recurse.

Go deep — follow one path as far as it goes before trying others. This is the "depth-first" part.

3
When there are no unvisited neighbors, return (backtrack).

The function returns to its caller, which tries the next unvisited neighbor. This is the "backtracking" part — it's automatic via the call stack.

The magic of recursion: Backtracking happens for free. When a recursive call finishes, execution returns to wherever it was called from. The call stack is your backtracking memory — you don't manage it manually. This is why recursive DFS looks so short.
THE CODE EMERGES
Chapter 4 of 6

Now the code writes itself.

Watch the three rules translate directly into code. Each line maps to exactly one rule.

dfs.pyPython
def dfs(graph, node, visited):
    # Rule 1: mark this node as visited
    visited.add(node)
    print(node)   # or do whatever you need here

    # Rule 2: recurse into every UNVISITED neighbor
    for neighbor in graph[node]:
        if neighbor not in visited:
            dfs(graph, neighbor, visited)

    # Rule 3: (implicit) when loop ends, function returns → backtrack


# How to call it: start from node 0
graph = {0:[1,2], 1:[0,3], 2:[0,3], 3:[1,2,4], 4:[3]}
dfs(graph, 0, set())
DFS.javaJava
void dfs(List<Integer>[] graph, int node, boolean[] visited) {
    // Rule 1: mark visited
    visited[node] = true;
    System.out.println(node);  // or do whatever you need here

    // Rule 2: recurse into every unvisited neighbor
    for (int neighbor : graph[node]) {
        if (!visited[neighbor]) {
            dfs(graph, neighbor, visited);
        }
    }
    // Rule 3: (implicit) method returns → backtrack
}

// How to call it:
boolean[] visited = new boolean[n];
dfs(graph, 0, visited);
That's the entire algorithm. 7 lines of logic. Every DFS you'll ever write is a variation of this. The only thing that changes is what you do with each node when you visit it — print it, count it, check a condition, add it to a result. The structure never changes.

The same thing, without recursion

Recursion uses the system's call stack implicitly. You can also manage the stack yourself with an explicit stack (a list). Same algorithm, same result — just more visible.

dfs_iterative.pyPython — Iterative DFS
def dfs_iterative(graph, start):
    visited = set()
    stack = [start]         # explicit stack replaces call stack

    while stack:
        node = stack.pop()  # pop = "go deeper" (LIFO)
        if node in visited:
            continue
        visited.add(node)
        print(node)

        for neighbor in graph[node]:
            if neighbor not in visited:
                stack.append(neighbor)  # push neighbors to explore later

    return visited
DFSIterative.javaJava — Iterative DFS
Set<Integer> dfsIterative(List<Integer>[] graph, int start) {
    Set<Integer> visited = new HashSet<>();
    Deque<Integer> stack = new ArrayDeque<>();
    stack.push(start);

    while (!stack.isEmpty()) {
        int node = stack.pop();
        if (visited.contains(node)) continue;
        visited.add(node);
        System.out.println(node);

        for (int neighbor : graph[node]) {
            if (!visited.contains(neighbor)) {
                stack.push(neighbor);
            }
        }
    }
    return visited;
}
Recursive vs Iterative DFS: Both visit nodes in depth-first order. Use recursive for cleaner code (most interview problems). Use iterative when the graph is very deep and you're worried about hitting Python's recursion limit (~1000 calls deep). Java's limit is higher but the same concern applies.

The key moment to watch: When DFS finishes a node and its call pops off the stack, execution returns to the previous frame — which then continues checking its own remaining neighbors. That's backtracking. It's not a special operation; it's just function return.

Counting connected components

The most common beginner graph problem is: "how many connected groups exist?" DFS solves this with one extra idea — run DFS from every unvisited node, counting how many times you start a fresh DFS.

connected_components.pyPython
def count_components(n, edges):
    # Step 0: build adjacency list
    graph = {i: [] for i in range(n)}
    for u, v in edges:
        graph[u].append(v)
        graph[v].append(u)

    visited = set()
    count = 0

    def dfs(node):
        visited.add(node)
        for nei in graph[node]:
            if nei not in visited:
                dfs(nei)

    # Try starting DFS from every node
    for node in range(n):
        if node not in visited:   # only start a new DFS if unvisited
            dfs(node)
            count += 1           # each new DFS start = new component

    return count

# Example: 5 nodes, 2 separate components
    print(count_components(5, [[0,1],[0,2],[3,4]]))  # → 2
ConnectedComponents.javaJava
int countComponents(int n, int[][] edges) {
    List<Integer>[] graph = new ArrayList[n];
    for (int i = 0; i < n; i++) graph[i] = new ArrayList<>();
    for (int[] e : edges) {
        graph[e[0]].add(e[1]);
        graph[e[1]].add(e[0]);
    }

    boolean[] visited = new boolean[n];
    int count = 0;
    for (int node = 0; node < n; node++) {
        if (!visited[node]) {
            dfs(graph, node, visited);
            count++;
        }
    }
    return count;
}
