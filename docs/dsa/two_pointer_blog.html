Two Pointers: The Collision Algorithm

Most people use two pointers. Few understand why they work. Once you see the core insight — two independent claims narrowing a search space — the whole family of problems collapses into one pattern.

20 min read · Interactive examples · Covers LC 11, 15, 42, 141, 167 & more
01

The Core Insight

Two claims, not two indices

Every intro course shows two pointers as a technique — "start one at the front, one at the back, move them inward". That's the mechanics. The insight is different.

Two pointers work whenever you can make two independent monotonic claims about a search space, and moving one pointer can only help (or definitively hurt) while leaving the other as-is. The pointers don't move randomly — each move eliminates a class of candidates that provably can't be the answer.

In Two Sum II (sorted array, find a pair summing to target): if the current sum is too small, the left pointer's current value is useless with every right pointer position — so move it right. If the sum is too large, the right pointer's value is useless — move it left. You're not guessing; you're eliminating.

Core Insight
Two pointers work whenever moving one pointer in a fixed direction is guaranteed to eliminate candidates that couldn't have been the answer anyway.

The key observation: the search space is an implicit n×n grid of all (L, R) pairs. Each step eliminates an entire row or column. That's why this runs in O(n) — you traverse at most 2n steps to cover the whole grid.

The Five Patterns

Most two-pointer problems collapse into five teachable shapes. The pointer mechanics change, but the core skill stays the same: move one pointer in a way that provably throws away candidates you no longer need to consider.

Pattern 1
Opposite Ends
Start at both ends, converge inward. Works on sorted arrays or symmetric structures. Sum too big → move R. Too small → move L.
LC 167, 11, 15, 42, 125
Pattern 2
Slow & Fast
Two pointers move with different roles or speeds. Used for linked-list cycles, midpoint/gap problems, and "fast discovers, slow acts" situations.
LC 141, 142, 19, 287, 234
Pattern 3
Read & Write
One pointer reads; another writes only valid elements. Classic in-place array transformation. Preserve order, eliminate O(n) space.
LC 26, 27, 80, 283, 75
Pattern 4
Sliding Window
Both pointers move in the same direction; the window expands when valid, shrinks when not. Find minimum/maximum subarray satisfying a condition.
LC 3, 76, 209, 424, 567
Pattern 5
Two Sequences
One pointer per array, list, or string. Advance the side that is "behind" and synchronize two ordered streams without extra passes.
LC 88, 349, 392, 165, 925
Recognition Shortcut
If the problem asks for a pair or triplet in a sorted structure → Pattern 1. If it involves a linked list cycle, gap, or midpoint → Pattern 2. If it's "remove/move/compress in-place" → Pattern 3. If it's "longest/shortest/count subarray with property X" → Pattern 4. If there are two arrays, two strings, or two sorted streams to compare or merge → Pattern 5.

The templates

Patterns 1–5 all look different on the surface, but each has a repeatable movement rule. Pick the right shape early and stick to it — mixing them is the main source of off-by-one and missed-case bugs.

Opposite Ends
// Precondition: sorted array (or symmetric structure)
int left = 0, right = nums.length - 1;

while (left < right) {
    int sum = nums[left] + nums[right];

    if (sum == target) {
        return new int[]{left + 1, right + 1};
    } else if (sum < target) {
        left++;   // too small — left value useless for all R
    } else {
        right--;  // too large — right value useless for all L
    }
}
return new int[]{-1, -1}; // no pair found
# Precondition: sorted array (or symmetric structure)
left, right = 0, len(nums) - 1

while left < right:
    total = nums[left] + nums[right]

    if total == target:
        return [left + 1, right + 1]
    elif total < target:
        left += 1   # too small — left value useless for all R
    else:
        right -= 1  # too large — right value useless for all L

return [-1, -1]  # no pair found

Sliding Window
int left = 0, best = 0;
// windowState tracks what's inside [left, right]

for (int right = 0; right < nums.length; right++) {
    windowState.add(nums[right]);   // expand

    while (!isValid(windowState)) {
        windowState.remove(nums[left]);
        left++;                      // shrink
    }

    best = Math.max(best, right - left + 1);
}
return best;
left = best = 0
window_state = {}  # or collections.Counter()

for right in range(len(nums)):
    window_state[nums[right]] = window_state.get(nums[right], 0) + 1  # expand

    while not is_valid(window_state):
        window_state[nums[left]] -= 1
        if window_state[nums[left]] == 0:
            del window_state[nums[left]]
        left += 1                    # shrink

    best = max(best, right - left + 1)

return best

⚠ Most Common Mistakes
(1) Wrong loop condition — use while (left < right) for opposite-ends (not <=, since L==R means one element). (2) Forgetting to skip duplicates in 3Sum — after finding a valid triplet, advance both pointers past identical values. (3) Fast pointer null check — always check fast != null && fast.next != null before accessing fast.next.next. (4) In two-sequence scans, don’t advance both sides unless you found a match or explicitly consumed both candidates.

Deep Dives

LC 42 — Trapping Rain Water (the hard one)

This is the problem that tests whether you truly understand the opposite-ends insight, not just memorized it. The naive O(n²) solution is obvious. The O(n) two-pointer solution requires a proof.

LC 42 Trapping Rain Water Hard 51.6% acceptance

Given n non-negative integers representing an elevation map where the width of each bar is 1, compute how much water it can trap after raining.

Example: height = [0,1,0,2,1,0,1,3,2,1,2,1] → Output: 6

The water trapped at index i = min(maxLeft[i], maxRight[i]) - height[i]. Precomputing these arrays takes O(n) space. The two-pointer approach eliminates that extra space.

The key invariant: if maxLeft < maxRight, the water at position L is determined solely by maxLeft — we don't need to know the exact right maximum, just that it's taller. So we can safely process L and advance it inward.

LC 42 — Trapping Rain Water
int left = 0, right = height.length - 1;
int maxLeft = 0, maxRight = 0, water = 0;

while (left <= right) {
    if (height[left] <= height[right]) {
        // right wall is taller — water[left] bounded by maxLeft
        maxLeft = Math.max(maxLeft, height[left]);
        water += maxLeft - height[left];
        left++;
    } else {
        maxRight = Math.max(maxRight, height[right]);
        water += maxRight - height[right];
        right--;
    }
}
return water;
left, right = 0, len(height) - 1
max_left = max_right = water = 0

while left <= right:
    if height[left] <= height[right]:
        # right wall is taller — water[left] bounded by max_left
        max_left = max(max_left, height[left])
        water += max_left - height[left]
        left += 1
    else:
        max_right = max(max_right, height[right])
        water += max_right - height[right]
        right -= 1

return water
The Elimination Argument
When height[L] ≤ height[R], the right side is a taller wall. Water at L is bounded by maxLeft, not by anything on the right (it's already taller). There's no value in keeping L here — process it and move on. This is the same "we can eliminate this candidate" logic from Two Sum II, just with a different condition.

LC 15 — 3Sum (the extension)

3Sum extends Pattern 1 to three numbers. The insight: fix one number with an outer loop, then use two pointers on the remainder. The tricky part is duplicate handling — you must skip over equal elements after finding a valid triplet, or after the outer loop advances.

LC 15 3Sum Medium 28.3% acceptance

Given an integer array nums, return all triplets [nums[i], nums[j], nums[k]] such that i ≠ j ≠ k and nums[i] + nums[j] + nums[k] == 0. The solution set must not contain duplicate triplets.

Example: nums = [-1,0,1,2,-1,-4] → Output: [[-1,-1,2],[-1,0,1]]

LC 15 — 3Sum
Arrays.sort(nums); // sort first — enables two pointers
List<List<Integer>> result = new ArrayList<>();

for (int i = 0; i < nums.length - 2; i++) {
    if (i > 0 && nums[i] == nums[i-1]) continue; // skip dup outer
    if (nums[i] > 0) break;               // sorted — can't sum to 0

    int left = i + 1, right = nums.length - 1;
    while (left < right) {
        int sum = nums[i] + nums[left] + nums[right];
        if (sum == 0) {
            result.add(Arrays.asList(nums[i], nums[left], nums[right]));
            while (left < right && nums[left] == nums[left+1]) left++;
            while (left < right && nums[right] == nums[right-1]) right--;
            left++; right--;
        } else if (sum < 0) left++;
        else right--;
    }
}
return result;
nums.sort()  # sort first — enables two pointers
result = []

for i in range(len(nums) - 2):
    if i > 0 and nums[i] == nums[i - 1]:
        continue          # skip duplicate outer
    if nums[i] > 0:
        break             # sorted — can't sum to 0

    left, right = i + 1, len(nums) - 1
    while left < right:
        total = nums[i] + nums[left] + nums[right]
        if total == 0:
            result.append([nums[i], nums[left], nums[right]])
            while left < right and nums[left] == nums[left + 1]:
                left += 1
            while left < right and nums[right] == nums[right - 1]:
                right -= 1
            left += 1
            right -= 1
        elif total < 0:
            left += 1
        else:
            right -= 1

return result
LC 15 vs LC 16 vs LC 18
LC 16 (3Sum Closest) is 3Sum but track minimum diff instead of exact match — same template, different bookkeeping. LC 18 (4Sum) wraps another outer loop around 3Sum — O(n³). The elimination logic is identical; you're just fixing more variables upfront.

Curriculum Map

The teaching structure is: 5 core patterns → a few memorable subpatterns under each → then a practice inventory. Learn the movement rule first, then use the problem table as drill material.

The Pattern-First Curriculum
Pattern 1 — Opposite Ends: pair sum, palindrome/reverse, area or water optimization, and "fix one + search the rest" like 3Sum.
Pattern 2 — Slow & Fast: cycle detection, cycle entry, midpoint/gap problems, and linked-list shape questions.
Pattern 3 — Read & Write: remove, compact, deduplicate, partition, and in-place overwrite.
Pattern 4 — Sliding Window: longest valid window, shortest valid window, count valid windows, and constraint-tracking windows.
Pattern 5 — Two Sequences: merge sorted data, intersections, subsequence checks, string/version comparison.

The 8-problem learning path

Do these in order. Each step adds one new pointer movement shape or a harder proof obligation.

1
LC 167 — Two Sum II
The purest Opposite Ends problem. The elimination argument is crystal clear: too big → R useless, too small → L useless. Do this before any other two-pointer problem even if it feels too easy.
2
LC 283 — Move Zeroes
Your first Read/Write problem. The read pointer scans everything; write only advances for non-zero. The pattern clicks immediately because the validity condition is obvious.
3
LC 141 — Linked List Cycle
Slow/fast pointer on a linked list. This one feels completely different from the array problems, which is exactly the point — the same two-pointer principle works in a completely different data structure.
4
LC 11 — Container With Most Water
Opposite Ends with a non-obvious condition. The elimination argument requires a proof: moving the taller wall can only decrease width without helping height, so it's never optimal. Forces you to think, not just apply the template.
5
LC 15 — 3Sum
Opposite Ends nested inside an outer loop. Tests duplicate handling — the subtle part most solutions miss. If you can do this cleanly, you can do 4Sum, kSum, and all their variants.
6
LC 3 — Longest Substring Without Repeating Characters
Your first Sliding Window problem. The expand/shrink logic is different from converging pointers but the same core idea: each pointer move eliminates candidates. Once this clicks, LC 76 and LC 209 feel identical.
7
LC 392 — Is Subsequence
The cleanest two-sequence scan. One string is strict, the other is generous. This introduces the “advance the side that is behind” mindset without the extra noise of merging or deduplication.
8
LC 88 — Merge Sorted Array
The classic merge shape. It looks different from the other patterns, but it is still just pointer coordination. Once this is comfortable, intersections, compare-version, and many string-matching variants become routine.

The three-question test

When you see a new problem, run through this mentally:

1
Is the input sorted, or can I sort it?
Sorting unlocks Opposite Ends (Pattern 1). If the problem says "sorted" or doesn't care about index preservation, you can sort first. O(n log n) sort is often fine when it enables O(n) two-pointer pass.
2
Can I eliminate a candidate by looking at boundary values?
If current sum/product/comparison too big → something can be dropped from the right. Too small → drop from the left. If yes, Pattern 1 or 2 likely applies.
3
Is this about in-place modification, a window, or two separate sequences?
"In-place" + "sorted/filtered" → Read/Write. "Subarray" + "min/max/count satisfying condition" → Sliding Window. "Two arrays / two strings / merge / compare" → Two Sequences. "Linked list" + anything structural → Slow/Fast.

The Mental Model

One sentence that covers everything

Two pointers work whenever moving one pointer in a fixed direction provably eliminates candidates that can't be the answer — and you can make that proof cheaply.

The sorted-array case is just the most obvious version. The linked list cycle, the in-place array transform, the sliding window, the two-sequence merge — they're all the same insight wearing different clothes. In each case, you're not searching blindly: you're using pointer movement to skip work in bulk.

Engineers who solve these problems fluently in interviews haven't memorized 100 solutions. They've internalized five movement shapes deeply enough to recognize them in new disguises. Build that recognition through the pattern-first path above, and the long problem list starts collapsing into a small number of reusable ideas.

Interview Sentence That Signals Expertise
"Moving the [left/right/slow/fast] pointer here provably eliminates candidates that couldn't be the answer — because [reason]. So the two-pointer approach runs in O(n) without missing a valid solution."
