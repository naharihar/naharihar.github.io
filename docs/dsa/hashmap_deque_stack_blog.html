01 — Core Insight

HashMap: O(1) Everything

HashMap's superpower is O(1) average-time lookup, insertion, and deletion. The moment a problem asks "have I seen this before?" or "how many times does X appear?", reach for HashMap first.

The Core Insight: HashMap trades space for time. Instead of scanning an array for a value (O(n)), you hash the key to its bucket in constant time. Almost every frequency-counting, caching, or grouping problem has a HashMap at its heart.

Pattern 2 · Two Sum / Complement Lookup
// Two Sum: find indices of two numbers that add to target
public int[] twoSum(int[] nums, int target) {
    Map<Integer, Integer> seen = new HashMap<>(); // value → index
    for (int i = 0; i < nums.length; i++) {
        int complement = target - nums[i];
        if (seen.containsKey(complement)) {
            return new int[] { seen.get(complement), i };
        }
        seen.put(nums[i], i);
    }
    return new int[] { -1, -1 };
}
def two_sum(nums, target):
    seen = {}  # value → index
    for i, n in enumerate(nums):
        complement = target - n
        if complement in seen:
            return [seen[complement], i]
        seen[n] = i
    return [-1, -1]
Pattern 3 · Prefix Sum + HashMap

Track running totals and use the map to find if a subarray sums to k in O(n). The key insight: if prefixSum[j] - prefixSum[i] == k, then subarray (i,j] sums to k.

// Count subarrays with sum == k (LC 560)
public int subarraySum(int[] nums, int k) {
    Map<Integer, Integer> prefixCount = new HashMap<>();
    prefixCount.put(0, 1);  // empty prefix has sum 0
    int count = 0, sum = 0;
    for (int n : nums) {
        sum += n;
        count += prefixCount.getOrDefault(sum - k, 0);
        prefixCount.put(sum, prefixCount.getOrDefault(sum, 0) + 1);
    }
    return count;
}
def subarray_sum(nums, k):
    prefix_count = {0: 1}  # empty prefix
    count, total = 0, 0
    for n in nums:
        total += n
        count += prefix_count.get(total - k, 0)
        prefix_count[total] = prefix_count.get(total, 0) + 1
    return count
Pattern 4 · Grouping / Anagram Bucketing
// Group anagrams (LC 49): same sorted key → same bucket
public List<List<String>> groupAnagrams(String[] strs) {
    Map<String, List<String>> groups = new HashMap<>();
    for (String s : strs) {
        char[] ch = s.toCharArray();
        Arrays.sort(ch);
        String key = new String(ch);
        groups.computeIfAbsent(key, k -> new ArrayList<>()).add(s);
    }
    return new ArrayList<>(groups.values());
}
from collections import defaultdict

def group_anagrams(strs):
    groups = defaultdict(list)
    for s in strs:
        key = "".join(sorted(s))   # sorted chars as key
        groups[key].append(s)
    return list(groups.values())

HashMap Problems Worth Studying

LC 560 · Subarray Sum Equals K Medium

Find the total number of continuous subarrays whose sum equals k. A naive O(n²) scan misses the insight: track prefix sums in a map.

Why it works: If prefix[j] - prefix[i] == k, then the subarray from i+1 to j sums to k. So for every j, we need to know how many previous prefix sums equal prefix[j] - k. The map stores exactly that count.

LC 128 · Longest Consecutive Sequence Medium

Find the longest run of consecutive integers in O(n) time. The trick: only start counting from sequence beginnings (nums[i]-1 not in set).

public int longestConsecutive(int[] nums) {
    Set<Integer> set = new HashSet<>();
    for (int n : nums) set.add(n);
    int best = 0;
    for (int n : set) {
        if (!set.contains(n - 1)) {  // only start of a sequence
            int len = 1;
            while (set.contains(n + len)) len++;
            best = Math.max(best, len);
        }
    }
    return best;
}
def longest_consecutive(nums):
    s = set(nums)
    best = 0
    for n in s:
        if n - 1 not in s:    # start of sequence
            length = 1
            while n + length in s: length += 1
            best = max(best, length)
    return best

01 — Core Insight

Deque: Double-Ended Power

A Deque (Double-Ended Queue) lets you push and pop from both the front and back in O(1). This makes it simultaneously a stack (LIFO) and a queue (FIFO) — and the backbone of the monotonic deque pattern.

The Core Insight: Use Deque when you need to efficiently maintain a window of candidates where outdated or dominated elements must be evicted from both ends. The monotonic deque is one of the most powerful and underused patterns in competitive programming.

Java gotcha: Never use Stack class as a stack in interviews. Use Deque<Integer> stack = new ArrayDeque<>() instead — it's faster, cleaner, and what interviewers expect.

The 3 Core Deque Patterns

Pattern 1 · BFS Queue

Deque as a FIFO queue is the backbone of BFS. Use offer() to enqueue and poll() to dequeue.

// BFS level-order traversal
Deque<TreeNode> queue = new ArrayDeque<>();
queue.offer(root);

while (!queue.isEmpty()) {
    int size = queue.size();  // capture level size
    for (int i = 0; i < size; i++) {
        TreeNode node = queue.poll();
        if (node.left != null)  queue.offer(node.left);
        if (node.right != null) queue.offer(node.right);
    }
}
from collections import deque

queue = deque([root])
while queue:
    size = len(queue)
    for _ in range(size):
        node = queue.popleft()       # poll = popleft
        if node.left:  queue.append(node.left)
        if node.right: queue.append(node.right)
Pattern 2 · Monotonic Deque (Sliding Window Max)

The monotonic deque maintains a window of candidates in decreasing order of value. When a new element enters, pop everything smaller from the back — they can never be the window max. When an element exits the window, pop from the front if it's the oldest candidate.

The elimination argument: If element B enters after element A and B ≥ A, then A will never be the window max while B is present. A is dominated. We can safely evict A. This is the key deduction that makes the deque O(n) instead of O(n²).

// Sliding Window Maximum (LC 239) — O(n)
public int[] maxSlidingWindow(int[] nums, int k) {
    Deque<Integer> dq = new ArrayDeque<>(); // stores INDICES
    int[] res = new int[nums.length - k + 1];

    for (int i = 0; i < nums.length; i++) {
        // Remove indices outside window
        while (!dq.isEmpty() && dq.peekFirst() < i - k + 1)
            dq.pollFirst();

        // Remove smaller elements from back (they're dominated)
        while (!dq.isEmpty() && nums[dq.peekLast()] < nums[i])
            dq.pollLast();

        dq.offerLast(i);

        if (i >= k - 1)
            res[i - k + 1] = nums[dq.peekFirst()]; // max = front
    }
    return res;
}
from collections import deque

def max_sliding_window(nums, k):
    dq = deque()  # stores indices
    res = []

    for i, n in enumerate(nums):
        # Remove out-of-window indices
        if dq and dq[0] < i - k + 1:
            dq.popleft()

        # Remove dominated elements from back
        while dq and nums[dq[-1]] < n:
            dq.pop()

        dq.append(i)
        if i >= k - 1:
            res.append(nums[dq[0]])
    return res
Pattern 3 · Bidirectional BFS / Palindrome Check
// Valid palindrome using deque
public boolean isPalindrome(String s) {
    Deque<Character> dq = new ArrayDeque<>();
    for (char c : s.toCharArray())
        if (Character.isLetterOrDigit(c))
            dq.offer(Character.toLowerCase(c));

    while (dq.size() > 1) {
        if (!dq.pollFirst().equals(dq.pollLast()))
            return false;
    }
    return true;
}
from collections import deque

def is_palindrome(s):
    dq = deque(c.lower() for c in s if c.isalnum())
    while len(dq) > 1:
        if dq.popleft() != dq.pop():
            return False
    return True

Deque Problems Worth Studying

LC 239 · Sliding Window Maximum Hard

Return the max of every window of size k. The monotonic deque solution is O(n) — each element is pushed and popped at most once.

Amortized O(n): Even though there's a while loop inside the for loop, each element enters the deque exactly once and leaves exactly once. Total work across all iterations = 2n = O(n).

LC 862 · Shortest Subarray with Sum At Least K Hard

Find shortest subarray with sum ≥ k. Combines prefix sums with a monotonic deque to find the best left boundary for each right pointer.

public int shortestSubarray(int[] nums, int k) {
    int n = nums.length;
    long[] prefix = new long[n + 1];
    for (int i = 0; i < n; i++) prefix[i+1] = prefix[i] + nums[i];

    Deque<Integer> dq = new ArrayDeque<>();
    int res = Integer.MAX_VALUE;

    for (int i = 0; i <= n; i++) {
        // Try to shrink window from left
        while (!dq.isEmpty() && prefix[i] - prefix[dq.peekFirst()] >= k)
            res = Math.min(res, i - dq.pollFirst());
        // Maintain increasing prefix sum order
        while (!dq.isEmpty() && prefix[i] <= prefix[dq.peekLast()])
            dq.pollLast();
        dq.offerLast(i);
    }
    return res == Integer.MAX_VALUE ? -1 : res;
}
from collections import deque

def shortest_subarray(nums, k):
    n = len(nums)
    prefix = [0] * (n + 1)
    for i in range(n): prefix[i+1] = prefix[i] + nums[i]

    dq = deque()
    res = float('inf')

    for i in range(n + 1):
        while dq and prefix[i] - prefix[dq[0]] >= k:
            res = min(res, i - dq.popleft())
        while dq and prefix[i] <= prefix[dq[-1]]:
            dq.pop()
        dq.append(i)
    return -1 if res == float('inf') else res

01 — Core Insight

Stack: LIFO and Nesting

A stack processes elements in Last-In-First-Out order. Its real power: matching and nesting problems. Whenever you see opening/closing pairs, "previous greater element", or "undo" semantics, a stack is almost certainly the right tool.

The Core Insight: Stack excels at problems where you need to defer a decision until you see a future element — like finding the next greater element for each position. Push candidates; pop and resolve them when the right future element arrives.

Java gotcha: java.util.Stack extends Vector and is considered legacy — it's synchronized and slow. Always use Deque<Integer> stack = new ArrayDeque<>() instead. Push = push() or addFirst(), Pop = pop() or removeFirst().

The 4 Core Stack Patterns

Pattern 1 · Matching Brackets / Parentheses

Push open brackets; when a close bracket appears, verify it matches the stack's top. The stack always holds the innermost unmatched open bracket.

public boolean isValid(String s) {
    Deque<Character> stack = new ArrayDeque<>();
    for (char c : s.toCharArray()) {
        if (c == '(' || c == '{' || c == '[') {
            stack.push(c);
        } else {
            if (stack.isEmpty()) return false;
            char top = stack.pop();
            if (c == ')' && top != '(') return false;
            if (c == '}' && top != '{') return false;
            if (c == ']' && top != '[') return false;
        }
    }
    return stack.isEmpty();
}
def is_valid(s):
    stack = []
    pairs = {')': '(', '}': '{', ']': '['}
    for c in s:
        if c in '([{':
            stack.append(c)
        else:
            if not stack or stack[-1] != pairs[c]:
                return False
            stack.pop()
    return not stack
Pattern 2 · Monotonic Stack (Next Greater Element)

Push indices onto a stack. When a new element is greater than the stack's top, the stack's top has found its "next greater element". Pop and record the answer.

The elimination argument: Once element B > element A and B comes after A, A will never be the "next greater" for anything to B's left that A hasn't already answered. Pop A, record B as A's answer. Stack only holds unanswered candidates.

// Next Greater Element (LC 496)
public int[] nextGreaterElement(int[] nums) {
    int n = nums.length;
    int[] res = new int[n];
    Arrays.fill(res, -1);
    Deque<Integer> stack = new ArrayDeque<>(); // stores indices

    for (int i = 0; i < n; i++) {
        // Pop all elements smaller than current
        while (!stack.isEmpty() && nums[stack.peek()] < nums[i]) {
            res[stack.pop()] = nums[i];
        }
        stack.push(i);
    }
    return res;
}

// Daily Temperatures (LC 739) — same pattern, answer = distance
public int[] dailyTemperatures(int[] temps) {

Pattern 3 · Min Stack / Stack with Extra Info
// Min Stack: track minimum alongside each element
class MinStack {
    Deque<int[]> stack = new ArrayDeque<>(); // [value, minSoFar]

    public void push(int val) {
        int min = stack.isEmpty() ? val : Math.min(val, stack.peek()[1]);
        stack.push(new int[] { val, min });
    }
    public void pop()    { stack.pop(); }
    public int  top()    { return stack.peek()[0]; }
    public int  getMin(){ return stack.peek()[1]; }
}
class MinStack:
    def __init__(self):
        self.stack = []  # stores (value, min_so_far)

    def push(self, val):
        cur_min = min(val, self.stack[-1][1]) if self.stack else val
        self.stack.append((val, cur_min))

    def pop(self):    self.stack.pop()
    def top(self):    return self.stack[-1][0]
    def getMin(self): return self.stack[-1][1]
Pattern 4 · Evaluate Expressions / Calculator
// Basic Calculator II (LC 227) — handles +, -, *, /
public int calculate(String s) {
    Deque<Integer> stack = new ArrayDeque<>();
    int num = 0; char op = '+';

    for (int i = 0; i < s.length(); i++) {
        char c = s.charAt(i);
        if (Character.isDigit(c)) num = num * 10 + (c - '0');
        if ((!Character.isDigit(c) && c != ' ') || i == s.length() - 1) {
            if      (op == '+') stack.push(num);
            else if (op == '-') stack.push(-num);
            else if (op == '*') stack.push(stack.pop() * num);
            else if (op == '/') stack.push(stack.pop() / num);
            op = c; num = 0;
        }
    }
    int result = 0;
    while (!stack.isEmpty()) result += stack.pop();
    return result;
}
def calculate(s):
    stack, num, op = [], 0, '+'
    s += '+'  # sentinel to flush last number

    for c in s:
        if c.isdigit():
            num = num * 10 + int(c)
        elif c in '+-*/':
            if   op == '+': stack.append(num)
            elif op == '-': stack.append(-num)
            elif op == '*': stack.append(stack.pop() * num)
            elif op == '/': stack.append(int(stack.pop() / num))
            op, num = c, 0
    return sum(stack)

Stack Problems Worth Studying

LC 84 · Largest Rectangle in Histogram Hard

Find the largest rectangle area in a histogram. The monotonic stack finds, for each bar, the nearest shorter bar on its left and right — defining the maximum width it can extend.

Why monotonic stack: Maintain an increasing stack. When a bar is shorter than the stack top, the top has found its right boundary. Its left boundary is the new stack top after popping. Area = height × (right - left - 1).

public int largestRectangleArea(int[] heights) {
    Deque<Integer> stack = new ArrayDeque<>();
    int max = 0;
    int[] h = Arrays.copyOf(heights, heights.length + 1); // sentinel 0

    for (int i = 0; i < h.length; i++) {
        while (!stack.isEmpty() && h[stack.peek()] > h[i]) {
            int height = h[stack.pop()];
            int width  = stack.isEmpty() ? i : i - stack.peek() - 1;
            max = Math.max(max, height * width);
        }
        stack.push(i);
    }
    return max;
}
def largest_rectangle_area(heights):
    stack = []
    max_area = 0
    heights = heights + [0]  # sentinel

    for i, h in enumerate(heights):
        while stack and heights[stack[-1]] > h:
            height = heights[stack.pop()]
            width = i if not stack else i - stack[-1] - 1
            max_area = max(max_area, height * width)
        stack.append(i)
    return max_area
