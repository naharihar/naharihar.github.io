THE 4 PATTERNS
Chapter 2 of 6

The patterns, one by one.

1
Connected Components
DFS or BFS — count separate groups of nodes
▾

The question: how many separate, disconnected groups exist in this graph? Or: is there any path from node A to node B?

The approach: loop through every node. If it's unvisited, launch a DFS/BFS from it — this explores the entire component it belongs to. Count how many times you launch a fresh search.

Recognition signals: "number of islands", "number of provinces", "find all groups", "connected components", "reachable from", "same group as"
1971. Find if Path Exists 547. Number of Provinces 200. Number of Islands 695. Max Area of Island 827. Making A Large Island
connected_components.pyPython
def count_components(n, edges):
    # Step 0: build adjacency list
    graph = [[] for _ in range(n)]
    for u, v in edges:
        graph[u].append(v)
        graph[v].append(u)

    visited = set()
    count = 0

    def dfs(node):
        visited.add(node)
        for nei in graph[node]:
            if nei not in visited:
                dfs(nei)

    for node in range(n):
        if node not in visited:  # start of a new component
            dfs(node)
            count += 1

    return count
The key loop: The outer for node in range(n) loop ensures we don't miss isolated nodes or disconnected components. Without it, we'd only explore the component containing the start node.
2
BFS Shortest Path
BFS only — minimum steps between two nodes
▾

The question: what is the minimum number of steps/hops to get from source to target? Every step costs the same (unweighted graph).

BFS is the only correct choice here. It explores level by level — all nodes at distance 1, then distance 2, and so on. The first time you reach the target is via the shortest path.

Recognition signals: "minimum steps", "minimum moves", "shortest path", "fewest operations", "least number of", "spread in minimum time", "degrees of separation"
994. Rotting Oranges 1091. Shortest Path in Binary Matrix 127. Word Ladder 542. 01 Matrix 317. Shortest Distance from All Buildings
bfs_shortest.pyPython
from collections import deque

def bfs_shortest(graph, start, target):
    if start == target: return 0
    visited = {start}
    queue = deque([(start, 0)])   # (node, distance)

    while queue:
        node, dist = queue.popleft()
        for nei in graph[node]:
            if nei == target:
                return dist + 1  # first reach = shortest
            if nei not in visited:
                visited.add(nei)
                queue.append((nei, dist + 1))
    return -1  # unreachable
Multi-source BFS: Some problems ask for the minimum distance from any of several sources to each node (e.g. "minimum distance to nearest 0"). Seed all sources into the queue at distance 0 at the start. BFS naturally handles the rest.
3
Cycle Detection
DFS with state tracking — does a loop exist?
▾

The question: does this graph contain a cycle? This matters for scheduling (can you complete all tasks?), dependency checking (is there a circular dependency?), and validating tree structures.

The approach depends on the graph type:

Undirected graph

Track the parent node. If you visit an already-visited neighbor that isn't your parent → cycle.

A–B–C–A is a cycle
A–B–A is just the parent edge
Directed graph

Track 3 states: unvisited, in-progress, done. If you reach an in-progress node → cycle.

A→B is ok
A→B→A is a cycle (B reaches A which is in-progress)
Recognition signals: "detect cycle", "can you finish all courses", "valid schedule", "circular dependency", "is this a valid tree"
207. Course Schedule 261. Graph Valid Tree 684. Redundant Connection 802. Find Eventual Safe States
cycle_directed.pyPython — Directed Graph (3-color DFS)
def has_cycle(n, edges):
    graph = [[] for _ in range(n)]
    for u, v in edges:
        graph[u].append(v)  # directed: only u→v

    # 0=unvisited, 1=in current path, 2=fully done
    state = [0] * n

    def dfs(node):
        state[node] = 1  # mark: currently exploring
        for nei in graph[node]:
            if state[nei] == 1:   # reached a node in current path!
                return True        # cycle found
            if state[nei] == 0 and dfs(nei):
                return True
        state[node] = 2  # mark: fully explored, no cycle through here
        return False

    return any(dfs(i) for i in range(n) if state[i] == 0)
Why 3 states and not 2? "Visited" (2 states) can't tell the difference between "I visited this node in a previous DFS call" and "I'm currently visiting this node right now." Only an in-progress node creates a cycle — a fully-done node does not.
4
Topological Sort
BFS (Kahn's) or DFS — order nodes by dependencies
▾

The question: given tasks with dependencies (A must come before B), what's a valid order to do them all? This only makes sense for directed graphs with no cycles (DAGs — Directed Acyclic Graphs).

Kahn's algorithm is the clearest approach: repeatedly remove nodes that have no prerequisites (in-degree = 0). Those are safe to do first. Once done, their dependents may now have no remaining prerequisites. Repeat until empty — or detect a cycle if you get stuck.

Recognition signals: "valid order", "prerequisites", "dependencies", "tasks that must happen before others", "build order", "course order", "schedule tasks"
210. Course Schedule II 207. Course Schedule 269. Alien Dictionary 329. Longest Increasing Path
topo_sort.pyPython — Kahn's Algorithm
from collections import deque

def topo_sort(n, edges):
    # Build graph + count incoming edges per node
    graph = [[] for _ in range(n)]
    indegree = [0] * n
    for u, v in edges:    # u must come BEFORE v
        graph[u].append(v)
        indegree[v] += 1

    # Start with all nodes that have NO prerequisites
    queue = deque(i for i in range(n) if indegree[i] == 0)
    order = []

    while queue:
        node = queue.popleft()
        order.append(node)
        for nei in graph[node]:
            indegree[nei] -= 1          # one prereq satisfied
            if indegree[nei] == 0:      # all prereqs done!
                queue.append(nei)

    # If order has all n nodes, no cycle. Otherwise cycle exists.
    return order if len(order) == n else []
Cycle detection is free: If the output order has fewer than n nodes, it means some nodes could never reach in-degree 0 — they're stuck in a cycle. Kahn's algorithm detects cycles as a side effect.

THE DECISION FRAMEWORK
Chapter 4 of 6

The 30-second
decision framework.

When you see a graph problem, run through these questions in order. You'll land on the right pattern almost every time.

❓
Does the problem mention "minimum", "shortest", "fewest", "least"? → Yes: use BFS (Pattern 2). Queue = level-by-level = shortest path guaranteed.
↓ No
❓
Does it ask for a valid ordering, or "can all tasks be completed"? → Yes: use Topological Sort (Pattern 4). Directed graph with dependencies.
↓ No
❓
Does it ask whether a cycle exists, or if a graph is a valid tree? → Yes: use Cycle Detection (Pattern 3). 3-color DFS for directed, parent-tracking for undirected.
↓ No
✓
Default: Connected Components (Pattern 1) Count groups, find if nodes are connected, explore regions. DFS/BFS with the outer for-loop.
The meta-rule: Build the adjacency list first, always. Before you write a single traversal line, build the graph. Then pick your pattern. Most interview mistakes happen because people skip step 0 and write traversal code directly on the edge list.

THE FULL PICTURE
Chapter 5 of 6

Every graph problem
in 5 steps.

No matter the problem, this sequence never changes. Internalise it and you'll never stare at a blank screen again.

1
Read the problem. Identify: is this a graph? Things with connections between them. Grid problems are graphs (cells = nodes, adjacent cells = edges).
2
Identify: directed or undirected? Weighted? Directed = one-way arrows. Undirected = mutual connections. Most beginner/mid problems are unweighted.
3
Build the adjacency list. Always. Even if the input is a matrix or edge list, convert to adjacency list first. This is step 0 of every solution.
4
Run the decision framework. Minimum? → BFS. Ordering? → Topo. Cycle? → Cycle detect. Count groups? → Components. Pick the template.
5
Write the solution. Start with your template. Add the problem-specific logic (what to count, what to return, what condition to check). Handle edge cases (empty graph, single node, unreachable target).
The template vs the logic: The traversal code (BFS loop, DFS recursion, Kahn's while-loop) never changes — copy it from memory. The only thing you write fresh each time is what you do with each node when you visit it. That's usually 1-3 lines.

Two things that trip people up

Trap 1

Forgetting the visited set

Every graph traversal needs one. Even if the problem says "no cycles," add it. It costs nothing and prevents silent infinite loops.

Trap 2

Using DFS for shortest path

The problem says "minimum" or "shortest." You write DFS. It fails half the test cases. Always: minimum = BFS. No exceptions on unweighted graphs.
