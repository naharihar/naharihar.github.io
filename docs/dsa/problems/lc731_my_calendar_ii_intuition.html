First Principles

How to think about “allow double, reject triple” bookings

The trick is not about counting every overlap from scratch. It is about remembering where overlap depth is already two, because those regions are now off-limits.

LC 731Pattern 3Track dangerous overlap zones
Human Version

Some timeline segments are still safe, some are already saturated

Mental model

A single-booked region can still accept one more meeting. A double-booked region cannot accept anything else.

So the important data is not just the bookings. It is the overlap regions that have already become double booked.

Brute Force

The naive method recomputes overlap depth every time

For each new booking, you could compare it against every old booking and try to count how many events cover each part of the interval. That gets messy fast because the same overlap regions are rediscovered again and again.

Optimization

Store the already-double-booked segments explicitly

Optimization insight A new booking should be rejected immediately if it intersects any segment that is already double booked. Otherwise, every intersection with existing single bookings creates new double-booked segments for the future.

That is why the standard solution keeps two lists: all bookings, and the overlap fragments created by pairs of bookings.

Spot It

Watch for bounded overlap depth

Whenever a problem says “allow up to k overlaps but not more,” try to explicitly represent the regions that have already reached the dangerous depth.
