First Principles

How to build Merge Intervals from the ground up

This one stops feeling like a bag of cases once you realize you only ever need to track one active merged block.

LC 56Pattern 2Active merge block
Human Version

We are compressing overlapping claims into blocks

Interpretation

If several intervals touch the same stretch of the timeline, the final answer should report that stretch only once.

The output is therefore a set of disjoint blocks covering the same total area as the input.

Brute Force

A direct approach keeps scanning for any overlapping pair

You could repeatedly find two intervals that overlap, merge them, replace them with one larger interval, and keep going until no overlap remains. That works, but it spends a lot of time rediscovering the same relationships.

Find an overlapping pairSearch across the list.
Merge themReplace them with one interval.
RepeatKeep rescanning until stable.
Optimization

Sorting by start time makes overlap local

Key simplification After sorting by start, if interval i does not overlap the current merged block, then no later interval can magically overlap that old block without first overlapping the current interval in front of it.

So instead of repeatedly merging arbitrary pairs, you keep one active interval and either extend it or flush it to the answer.

Spot It

Use this when the output wants disjoint ranges

If a problem says “merge,” “collapse,” “compress,” or “coalesce” overlapping ranges, sort by start and ask whether overlap becomes a local scan problem.
