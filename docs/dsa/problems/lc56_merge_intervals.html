Merge Intervals

This is the “compress overlapping claims into one block” version of interval thinking. Once intervals are sorted by start time, overlap becomes a local decision.

Official LeetCode problem ↗ Build this from first principles ↗
Problem

Combine every group of overlapping intervals into one

Plain-English Statement

You are given several intervals. Some overlap and some do not. Your job is to combine every overlapping group into a single interval that covers the full range of that group.

Return the final list of non-overlapping merged intervals.

Original Example
Inputintervals = [[1,3],[2,6],[8,10],[15,18]]
Output[[1,6],[8,10],[15,18]]
Why[1,3] and [2,6] overlap, so together they become [1,6].
Intuition

Sort by start time and maintain one active merged block

If intervals are sorted by their start time, then any interval that overlaps the current merged block must appear right next to it in the scan. That means we never need to jump around or compare every pair against every other pair.

Active block idea Keep one interval called current. If the next interval starts before or at current.end, it belongs to the same merged group, so extend the end. Otherwise, the current block is finished and you can start a new one.
Scan Rule
if nextStart <= currentEnd, merge; otherwise, flush current block
[1,3]
[2,6]
→ [1,6]

The only moving part is the right boundary of the current merged interval.

Solution

Sort once, then merge in one linear pass

import java.util.*;

class Solution {
    public int[][] merge(int[][] intervals) {
        Arrays.sort(intervals, (a, b) -> Integer.compare(a[0], b[0]));
        List<int[]> merged = new ArrayList<>();

        int[] current = intervals[0];
        for (int i = 1; i < intervals.length; i++) {
            if (intervals[i][0] <= current[1]) {
                current[1] = Math.max(current[1], intervals[i][1]);
            } else {
                merged.add(current);
                current = intervals[i];
            }
        }
        merged.add(current);
        return merged.toArray(new int[merged.size()][]);
    }
}
class Solution:
    def merge(self, intervals):
        intervals.sort(key=lambda iv: iv[0])
        merged = [intervals[0]]

        for start, end in intervals[1:]:
            if start <= merged[-1][1]:
                merged[-1][1] = max(merged[-1][1], end)
            else:
                merged.append([start, end])

        return merged
Time
O(n log n)

Sorting dominates the merge pass.

Space
O(n)

The merged output can hold up to all intervals.
