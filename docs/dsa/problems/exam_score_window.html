Exam Score Window

A real gradebook stores [score, studentId] pairs sorted by score. Two binary searches on the score column find exactly which students hit a target — and who they are.

Problem

What are we solving?

Problem Statement

You are given a 2D array students[][] sorted by score in non-decreasing order, where students[i][0] is the exam score and students[i][1] is the student ID. Given a target score, return [first, last] — the indices of the first and last student who scored exactly target. Return [-1, -1] if no student scored that value.

Data shape — students[i]
students[i][0] → score the sort key — binary search on this
students[i][1] → studentId payload — retrieved after finding the window
The array is sorted by students[i][0]. Student IDs within the same score band are in insertion order — no secondary sort is guaranteed.
Example 1 — target exists with duplicates
students[[52,1041],[61,2093],[74,3017],[74,1182],[74,4450],[88,2211],[91,3309],[91,1774],[95,5001]]
target74
Output[2, 4]

students[2][0]=74 is the first 74 (student #3017). students[4][0]=74 is the last 74 (student #4450). Three students scored 74.

Example 2 — target not present
target80
Output[-1, -1]

No row has score 80. Both searches return -1.

Intuition

Binary search on students[mid][0] — everything else is identical

The only change from a plain integer array: comparisons use students[mid][0] (the score column) instead of scores[mid]. The two templates — hunt left for first, hunt right for last — are unchanged.

Template 1 — Find FIRST (hunt left)
int lo=0, hi=n-1, first=-1;
while(lo <= hi) {
  int mid = lo+(hi-lo)/2;
  int s = students[mid][0];
  if      (s < target) lo=mid+1;
  else if(s > target) hi=mid-1;
  else {
    first=mid;     // save
    hi=mid-1;      // go LEFT
  }
}
return first;
Template 2 — Find LAST (hunt right)
int lo=0, hi=n-1, last=-1;
while(lo <= hi) {
  int mid = lo+(hi-lo)/2;
  int s = students[mid][0];
  if      (s < target) lo=mid+1;
  else if(s > target) hi=mid-1;
  else {
    last=mid;      // save
    lo=mid+1;      // go RIGHT
  }
}
return last;
The one-line rule on a hitTemplate 1: ans = mid; hi = mid - 1 — save, search left for an earlier match.
Template 2: ans = mid; lo = mid + 1 — save, search right for a later match.
Everything else in both templates is identical.

Solution

Two binary searches on the score column

class Solution {

    public int[] scoreWindow(int[][] students, int target) {
        int first = findFirst(students, target);
        if (first == -1) return new int[]{-1, -1}; // not found — skip second search
        int last  = findLast(students, target);
        return new int[]{first, last};
    }

    // Template 1 — hunt left on every hit
    private int findFirst(int[][] students, int target) {
        int lo = 0, hi = students.length - 1, ans = -1;
        while (lo <= hi) {
            int mid = lo + (hi - lo) / 2;
            int score = students[mid][0];
            if      (score < target) lo = mid + 1;
            else if(score > target) hi = mid - 1;
            else { ans = mid; hi = mid - 1; } // hit → save, go LEFT
        }
        return ans;
    }

    // Template 2 — hunt right on every hit
    private int findLast(int[][] students, int target) {
        int lo = 0, hi = students.length - 1, ans = -1;
        while (lo <= hi) {
            int mid = lo + (hi - lo) / 2;
            int score = students[mid][0];
            if      (score < target) lo = mid + 1;
            else if(score > target) hi = mid - 1;
            else { ans = mid; lo = mid + 1; } // hit → save, go RIGHT
        }
        return ans;
    }

    // Bonus: return the student IDs in the score window
    public int[] studentsInBand(int[][] students, int target) {
        int[] window = scoreWindow(students, target);
        if (window[0] == -1) return new int[0];
        int count = window[1] - window[0] + 1;
        int[] ids = new int[count];
        for (int i = 0; i < count; i++)
            ids[i] = students[window[0] + i][1]; // extract studentId column
        return ids;
    }
}
from typing import List

class Solution:
    def score_window(self, students: List[List[int]], target: int) -> List[int]:
        first = self.find_first(students, target)
        if first == -1: return [-1, -1]  # not found — skip second search
        last = self.find_last(students, target)
        return [first, last]

    # Template 1 — hunt left on every hit
    def find_first(self, students, target):
        lo, hi, ans = 0, len(students) - 1, -1
        while lo <= hi:
            mid = lo + (hi - lo) // 2
            s = students[mid][0]
            if   s < target: lo = mid + 1
            elif s > target: hi = mid - 1
            else: ans = mid; hi = mid - 1  # hit → save, go LEFT
        return ans

    # Template 2 — hunt right on every hit
    def find_last(self, students, target):
        lo, hi, ans = 0, len(students) - 1, -1
        while lo <= hi:
            mid = lo + (hi - lo) // 2
            s = students[mid][0]
            if   s < target: lo = mid + 1
            elif s > target: hi = mid - 1
            else: ans = mid; lo = mid + 1  # hit → save, go RIGHT
        return ans

    # Bonus: return student IDs in the score window
    def students_in_band(self, students, target):
        first, last = self.score_window(students, target)
        if first == -1: return []
        return [students[i][1] for i in range(first, last + 1)]
Small optimization: skip second search if first returns -1If findFirst returns -1, target is absent. No need to run findLast. Return [-1, -1] immediately. Saves O(log n) in the not-found case.

Complexity

Time
O(log n)
Two binary searches, each O(log n). Extracting student IDs from the window is O(k) where k = count of matches — paid only when results exist.
Space
O(1)
Searches use only index pointers. The ID extraction result array is O(k) but that is output space, not auxiliary space.
Edge cases(1) Target absent → [-1, -1]. (2) Exactly one match → first == last, one student ID. (3) All rows same score → first=0, last=n-1. (4) Student IDs within a score band are unordered — do not assume any relationship between ID and rank.
