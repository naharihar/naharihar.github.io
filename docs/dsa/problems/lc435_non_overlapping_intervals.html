Non-overlapping Intervals

This is the cleanest starting point for the scheduling family. Once you trust the “keep the interval that ends earliest” instinct here, a lot of the later greedy patterns stop feeling magical.

Official LeetCode problem ↗ Build this from first principles ↗
Problem

Remove the fewest intervals so the rest no longer collide

Plain-English Statement

You are given several time intervals. Some overlap each other and some do not.

Your job is to remove as few intervals as possible so that the intervals left behind are pairwise non-overlapping.

Original Example
Inputintervals = [[1,2],[2,3],[3,4],[1,3]]
Output1
WhyIf you remove [1,3], the remaining three intervals fit without conflict.
Intuition

Think about what to keep, not what to remove

The problem becomes simpler once you flip the question. Instead of asking “which interval should I delete?”, ask “how many intervals can I safely keep?”

Key reframing minimum removals = total intervals - maximum intervals kept

That reframed version is classic interval scheduling. If two intervals compete for future time, the safer one to keep is the one that finishes earlier, because it leaves more room for what comes next.

Greedy Boundary
keep interval if nextStart >= lastAcceptedEnd
[1,2]
keep
[2,3]
keep
[1,3]
drop
[3,4]
keep

Sorting by end time makes every decision local: either the next interval fits after the current boundary or it does not.

Solution

Sort by end time and count the intervals that cannot fit

import java.util.Arrays;

class Solution {
    public int eraseOverlapIntervals(int[][] intervals) {
        Arrays.sort(intervals, (a, b) -> Integer.compare(a[1], b[1]));

        int removed = 0;
        int lastEnd = intervals[0][1];

        for (int i = 1; i < intervals.length; i++) {
            if (intervals[i][0] < lastEnd) {
                removed++;
            } else {
                lastEnd = intervals[i][1];
            }
        }

        return removed;
    }
}
class Solution:
    def eraseOverlapIntervals(self, intervals):
        intervals.sort(key=lambda iv: iv[1])

        removed = 0
        last_end = intervals[0][1]

        for start, end in intervals[1:]:
            if start < last_end:
                removed += 1
            else:
                last_end = end

        return removed
Time
O(n log n)

Sorting dominates the final scan.

Space
O(1)

Ignoring the sort implementation.
