First Principles

How to recognize weighted interval scheduling when profits appear

The moment a problem asks for maximum value instead of maximum count, pure greedy should make you suspicious. That is the pivot point into DP.

LC 1235Pattern 4DP + binary search
Human Version

Each job creates a take-or-skip fork

Core question

If you stand at one job, there are only two meaningful choices: take it and then jump to the last compatible profit, or skip it and keep the best answer from earlier jobs.

Brute Force

The direct recursion is “take or skip” at every job

That gives the right mental model immediately. But many branches keep asking the same compatibility question and the same suffix-profit question again and again.

Skip branchBest answer stays whatever was possible before this job.
Take branchAdd current profit and move to the latest job ending before this one starts.
Optimization

Sort by end time so both the DP and the compatibility lookup become structured

Optimization insight Once jobs are sorted by end time, the best answer up to index i becomes a natural DP state, and the last compatible job can be found with binary search instead of a backward scan.

This is the standard weighted interval scheduling recipe: value objective means DP, sorted ends make compatibility searchable.

Spot It

Intervals plus rewards almost always means weighted scheduling

If intervals carry profits, earnings, tips, or scores, and you must avoid overlap, think “weighted interval scheduling” before trying to force a greedy argument.
