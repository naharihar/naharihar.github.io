First Principles

How to see Single-Threaded CPU as “arrivals plus best available job”

This problem gets much simpler when you separate tasks that have already arrived from tasks that are still in the future.

LC 1834Pattern 4 / HeapArrival sweep
Human Version

The CPU only chooses from tasks that already exist at current time

Key split

Future tasks are not eligible yet. Among the tasks that have already arrived, the CPU chooses the one with shortest processing time, breaking ties by index.

Brute Force

A naive simulation rescans all tasks at every choice point

You could repeatedly scan the entire input to find which tasks have arrived and which eligible task should run next. That works, but it wastes time rechecking tasks that were already known to be future tasks.

Optimization

Sort future arrivals once, then use a heap for current candidates

Two buckets Future tasks want ordering by enqueue time. Available tasks want ordering by processing time and index. A sorted list plus heap matches those two jobs exactly.

Whenever the heap is empty, time jumps to the next arrival instead of inching forward one unit at a time.

Spot It

Think “arrival stream + best current candidate”

If items become eligible over time and every decision must choose the best current item by a different rule, expect a sorted arrival list plus a heap of active choices.
