Maximum Length of Pair Chain

This is interval scheduling wearing a different outfit. Once you translate each pair into an interval, the greedy choice is exactly the same as the earliest-finish rule.

Official LeetCode problem ↗ Build this from first principles ↗
Problem

Build the longest valid chain of pairs

Plain-English Statement

You are given several pairs of numbers. Each pair looks like [a, b] where a < b.

You want to build the longest possible chain. A pair [c, d] can come after [a, b] only if b < c.

Return the maximum number of pairs you can arrange into one valid chain.

Original Example
Inputpairs = [[1,2],[2,3],[3,4]]
Output2
Why[1,2] -> [3,4] works because 2 < 3, but [1,2] -> [2,3] does not.
Intuition

Translate pairs into intervals and then use the same greedy rule

The problem feels new only because the input is described as pairs instead of meetings or balloons. Structurally, each pair is just an interval with a start and an end.

Translation step Pair [a, b] behaves like an interval that starts at a and ends at b. The chain rule b < c is just the “next interval must start after the current one ends” rule.

Once you see that translation, the right greedy decision is the same as LC 435: keep the pair that ends earliest because it preserves the most room for future choices.

Greedy Shape
take pair if nextStart > lastChosenEnd
[1,2]
[2,3]
[3,4]

The strict inequality is the only twist here: touching endpoints do not chain.

Solution

Sort by ending value and greedily extend the chain

import java.util.Arrays;

class Solution {
    public int findLongestChain(int[][] pairs) {
        Arrays.sort(pairs, (a, b) -> Integer.compare(a[1], b[1]));

        int count = 0;
        int lastEnd = Integer.MIN_VALUE;

        for (int[] pair : pairs) {
            if (pair[0] > lastEnd) {
                count++;
                lastEnd = pair[1];
            }
        }

        return count;
    }
}
class Solution:
    def findLongestChain(self, pairs):
        pairs.sort(key=lambda p: p[1])

        count = 0
        last_end = float('-inf')

        for start, end in pairs:
            if start > last_end:
                count += 1
                last_end = end

        return count
Time
O(n log n)

Sorting the pairs dominates the scan.

Space
O(1)

Ignoring the sort implementation.
