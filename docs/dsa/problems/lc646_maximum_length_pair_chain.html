Maximum Length of Pair Chain

This is interval scheduling wearing a different outfit. Once you translate each pair into an interval, the greedy choice becomes exactly the same as non-overlapping intervals.

Official LeetCode problem ↗
Problem

Build the longest valid chain of pairs

Plain-English Statement

You are given several pairs of numbers. Each pair looks like [a, b] where a < b.

You want to build the longest possible chain. A pair [c, d] can come after [a, b] only when the earlier pair finishes strictly before the next one begins, which means b < c.

You do not need to use every pair. Return the maximum number of pairs you can place into one valid chain.

Original Example
Inputpairs = [[1,2],[2,3],[3,4]]
Output2
Why[1,2] -> [3,4] works because 2 < 3. But [1,2] -> [2,3] does not work because 2 < 2 is false.
Intuition

Treat each pair like an interval and keep the one that ends earliest

The first-principles version of the problem is: “I need the most non-overlapping items, where one item must end before the next one starts.” That is the same structure as interval scheduling.

Translation step Pair [a, b] behaves like an interval that starts at a and ends at b. The chain rule b < c is just the non-overlap rule for this problem.

Once the pairs are viewed as intervals, the greedy choice is natural: if two candidates are competing to be used next, the one that ends earlier leaves more room for future pairs.

After sorting by ending value, the only thing that matters is whether the next pair starts strictly after the end of the last chosen pair.

Step 1Sort pairs by their second value. For [[1,2],[2,3],[3,4]], the order already stays the same.
Step 2Take [1,2]. It ends earliest, so it is the safest first choice.
Step 3Check [2,3]. It starts at 2, but the rule needs start > lastEnd. Since 2 > 2 is false, skip it.
Step 4Check [3,4]. Now 3 > 2 is true, so take it.
Step 5The final chain length is 2.
Solution

Sort by end value and greedily extend the chain

We sort by the second number of each pair, then scan from left to right. Whenever a pair starts after the end of the last chosen pair, we add it to the chain and update the boundary.

import java.util.Arrays;

class Solution {
    public int findLongestChain(int[][] pairs) {
        Arrays.sort(pairs, (a, b) -> Integer.compare(a[1], b[1]));

        int count = 0;
        int lastEnd = Integer.MIN_VALUE;

        for (int[] pair : pairs) {
            if (pair[0] > lastEnd) {
                count++;
                lastEnd = pair[1];
            }
        }

        return count;
    }
}
class Solution:
    def findLongestChain(self, pairs):
        pairs.sort(key=lambda p: p[1])

        count = 0
        last_end = float('-inf')

        for start, end in pairs:
            if start > last_end:
                count += 1
                last_end = end

        return count
Time
O(n log n)

Sorting the pairs dominates the single pass.

Space
O(1)

Ignoring the sort implementation.
