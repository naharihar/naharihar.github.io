First Principles

How to discover the idea behind Non-overlapping Intervals

The clean entry point into interval scheduling is to stop focusing on deletions. The real job is choosing the largest set of intervals that can peacefully coexist.

LC 435Pattern 1 / 2Greedy by end time
Human Version

What are we really optimizing?

Reframe

You are not truly “removing intervals.” You are selecting a set of intervals that do not overlap.

Once that set is as large as possible, everything else is exactly what must be removed.

Key identityremoved = total - kept
Brute Force

The direct idea is to try all keep-or-skip choices

A first-principles recursive solution would stand at each interval and ask:

Option 1Skip this interval and move on.
Option 2Keep this interval if it does not overlap the last one you kept.
GoalMaximize how many intervals survive.

That works conceptually, but it explodes because many branches are repeating the same “what is the best I can do after this time boundary?” question.

Optimization

The only decision that matters is which interval frees the timeline earliest

Greedy insight When two intervals compete, the one ending earlier is always safer to keep because it leaves at least as much room for everything that follows.

That means we do not need to explore all subsets. We can sort by end time and make one local choice repeatedly: keep the next interval only if it starts after the current boundary.

Brute force
Try combinations

Repeatedly reconsider future choices after every keep/skip branch.

Optimized
Sort by end

One linear scan after sorting because the greedy rule is trustworthy.

Spot It

When should this pattern jump out at you?

If the problem says “remove minimum intervals,” “keep maximum compatible intervals,” or “select the largest non-overlapping subset,” you are usually looking at earliest-finish greedy scheduling.
