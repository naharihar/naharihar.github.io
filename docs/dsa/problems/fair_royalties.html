Original Problem Binary Search on Answer Prefix Sums Hard

Fair Royalties

The cost function is non-linear (squared). Prefix sums unlock O(1) range queries; binary search finds the minimum cap without exploring all splits.

Problem

What are we solving?

Problem Statement

A book has n chapters with page counts pages[i]. A publisher splits it into exactly k contiguous parts for k editors. Editor j's royalty is the square of the total pages in their part — longer parts earn disproportionately more. Minimize the maximum royalty any single editor earns.

Example
pages[4, 3, 2, 5, 1, 6]
k3
Output81

Best split: [4,3,2] → 9² = 81  |  [5,1] → 6² = 36  |  [6] → 6² = 36. Max = 81. Other splits produce a larger maximum.

Intuition

Minimize the maximum — binary search the royalty cap

Instead of finding the best split directly, binary search the answer R and ask: "if no editor may earn more than R, can we split the book into exactly k parts?"

The royalty cap R is monotone: if R works, R+1 also works. Binary search finds the boundary.

At R=81: [4,3,2]=9²=81 ✓  |  [5,1]=6²=36 ✓  |  [6]=6²=36 ✓. Fits in 3 parts. Answer = 81.

The feasibility check (greedy + prefix sums)

For a given cap R: walk left to right. Extend the current part as long as sum² ≤ R. When the next chapter would exceed it, close the part and start a new one. Count parts used — if ≤ k, feasible.

The key trick: checking whether adding chapter i would push the part's sum² over R means we need the running page sum quickly. We use prefix sums for O(1) range sum queries instead of re-summing from scratch each time.

Why prefix sums matter here Without prefix sums, each greedy step would need to re-sum a range. With prefix[i] = pages[0] + ... + pages[i-1], the sum of any range [l..r] is just prefix[r+1] - prefix[l] — O(1). This keeps the feasibility check O(n) rather than O(n²).

Solution

Binary search on the royalty cap

public class Solution {

    public long minMaxRoyalty(int[] pages, int k) {
        int n = pages.length;
        // prefix sums for O(1) range queries
        long[] prefix = new long[n + 1];
        for (int i = 0; i < n; i++) prefix[i+1] = prefix[i] + pages[i];

        // lo: at least one chapter must fit → min single-chapter royalty
        // hi: one part takes all chapters
        long lo = 0, hi = prefix[n] * prefix[n];
        for (int p : pages) lo = Math.max(lo, (long) p * p);

        while (lo < hi) {
            long mid = lo + (hi - lo) / 2;
            if (canSplit(prefix, k, mid)) {
                hi = mid;
            } else {
                lo = mid + 1;
            }
        }
        return lo;
    }

    private boolean canSplit(long[] prefix, int k, long maxR) {
        int n = prefix.length - 1;
        int parts = 0, start = 0;
        while (start < n) {
            // find the furthest end such that sum² ≤ maxR
            int end = start;
            while (end < n) {
                long rangeSum = prefix[end+1] - prefix[start];
                if (rangeSum * rangeSum > maxR) break;
                end++;
            }
            if (end == start) return false; // single chapter exceeds cap
            parts++;
            start = end;
        }
        return parts <= k;
    }

    public static void main(String[] args) {
        Solution sol = new Solution();
        int[] pages = {4, 3, 2, 5, 1, 6};
        System.out.println(sol.minMaxRoyalty(pages, 3)); // 81
    }
}
from typing import List
import math

class Solution:
    def min_max_royalty(self, pages: List[int], k: int) -> int:
        n = len(pages)
        prefix = [0] * (n + 1)
        for i in range(n):
            prefix[i+1] = prefix[i] + pages[i]

        lo = max(p*p for p in pages)  # min possible: each chapter is its own part
        hi = prefix[n] ** 2             # max possible: all chapters in one part

        while lo < hi:
            mid = lo + (hi - lo) // 2
            if self.can_split(prefix, k, mid):
                hi = mid
            else:
                lo = mid + 1
        return lo

    def can_split(self, prefix, k, max_r):
        n = len(prefix) - 1
        parts, start = 0, 0
        while start < n:
            end = start
            while end < n:
                range_sum = prefix[end+1] - prefix[start]
                if range_sum * range_sum > max_r: break
                end += 1
            if end == start: return False  # single chapter too big
            parts += 1
            start = end
        return parts <= k


if __name__ == "__main__":
    s = Solution()
    print(s.min_max_royalty([4,3,2,5,1,6], 3))  # 81

Complexity

Time
O(n log S²)
S = sum(pages). Binary search over [max_page², S²]; each step O(n) greedy with O(1) prefix lookups.
Space
O(n)
Prefix sum array of length n+1.
Binary search bounds — be careful with squares The search space is royalties (squared values), not page sums. Set lo = max(pages[i]²) and hi = sum(pages)². These can be very large — use long in Java or Python's native big ints.
