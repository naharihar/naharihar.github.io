LC 1834 Pattern 4 / heap Medium

Single-Threaded CPU

This is scheduling with release times: tasks arrive over time, and whenever the CPU is free it picks the shortest available task, breaking ties by index.

Official LeetCode problem ↗ Build this from first principles ↗
Problem

Return the order in which the CPU processes tasks

Plain-English Statement

Each task has an enqueue time and a processing time. The CPU can process only one task at a time. Whenever it becomes free, it chooses the available task with the smallest processing time, breaking ties by smaller original index.

Return the order of task indices processed by the CPU.

Intuition

Sort by arrival, then use a heap for currently available tasks

Tasks that have not arrived yet should not even be candidates. So we sort by enqueue time to know when each task becomes eligible. Among the eligible tasks, a min-heap gives the shortest processing time instantly.

Simulation pattern Keep a clock. Push every task whose enqueue time is <= current time into the heap. If the heap is empty, jump the clock to the next arrival. Otherwise, pop the shortest job and advance time by its processing length.
Solution

Arrival-order scan + min-heap by processing time and index

import java.util.*;

class Solution {
    public int[] getOrder(int[][] tasks) {
        int n = tasks.length;
        int[][] jobs = new int[n][3];
        for (int i = 0; i < n; i++) {
            jobs[i] = new int[] {tasks[i][0], tasks[i][1], i};
        }
        Arrays.sort(jobs, (a, b) -> Integer.compare(a[0], b[0]));

        PriorityQueue<int[]> heap = new PriorityQueue<>((a, b) ->
            a[1] == b[1] ? Integer.compare(a[2], b[2]) : Integer.compare(a[1], b[1]));

        long time = 0;
        int i = 0, idx = 0;
        int[] order = new int[n];

        while (i < n || !heap.isEmpty()) {
            if (heap.isEmpty() && time < jobs[i][0]) {
                time = jobs[i][0];
            }
            while (i < n && jobs[i][0] <= time) {
                heap.offer(jobs[i++]);
            }
            int[] job = heap.poll();
            order[idx++] = job[2];
            time += job[1];
        }
        return order;
    }
}
import heapq

class Solution:
    def getOrder(self, tasks):
        jobs = sorted((enqueue, process, i) for i, (enqueue, process) in enumerate(tasks))
        heap = []
        time = 0
        i = 0
        order = []

        while i < len(jobs) or heap:
            if not heap and time < jobs[i][0]:
                time = jobs[i][0]

            while i < len(jobs) and jobs[i][0] <= time:
                enqueue, process, index = jobs[i]
                heapq.heappush(heap, (process, index, enqueue))
                i += 1

            process, index, enqueue = heapq.heappop(heap)
            order.append(index)
            time += process

        return order
Time
O(n log n)

Sort once, then each task enters and leaves the heap once.

Space
O(n)

The heap may store all not-yet-processed available tasks.
