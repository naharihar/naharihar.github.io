Course Schedule III

This is deadline scheduling with a running time budget. The greedy step is not “take everything that fits,” but “whenever you are over budget, throw away the single course wasting the most time.”

Official LeetCode problem ↗ Build this from first principles ↗
Problem

Take as many courses as possible before their deadlines

Plain-English Statement

Each course has a duration and a closing deadline. You can take only one course at a time, and once a course starts you spend its full duration before moving on.

Return the maximum number of courses you can finish before their deadlines.

Original Example
Inputcourses = [[100,200],[200,1300],[1000,1250],[2000,3200]]
Output3
WhyThe long [2000,3200] course can still fit after keeping three earlier courses, but the [1000,1250] course blocks too much if taken with everything else.
Intuition

Always keep the shortest total schedule possible

Sorting by deadline is still the right first move because nearer deadlines constrain you first. But a simple “take if it fits” greedy is not enough. A long course can crowd out several shorter ones that appear later.

Swap insight If your chosen set is now too long to meet the current deadline, the worst course to keep is the one with the largest duration. Removing it frees the most time while losing only one course.

The max-heap is not choosing what to add next. It is repairing the set whenever the schedule becomes too long.

Solution

Sort by deadline, then use a max-heap of chosen durations

import java.util.*;

class Solution {
    public int scheduleCourse(int[][] courses) {
        Arrays.sort(courses, (a, b) -> Integer.compare(a[1], b[1]));
        PriorityQueue<Integer> maxHeap = new PriorityQueue<>(Collections.reverseOrder());
        int time = 0;

        for (int[] course : courses) {
            time += course[0];
            maxHeap.offer(course[0]);

            if (time > course[1]) {
                time -= maxHeap.poll();
            }
        }

        return maxHeap.size();
    }
}
import heapq

class Solution:
    def scheduleCourse(self, courses):
        courses.sort(key=lambda c: c[1])
        max_heap = []
        time = 0

        for duration, deadline in courses:
            time += duration
            heapq.heappush(max_heap, -duration)

            if time > deadline:
                time += heapq.heappop(max_heap)

        return len(max_heap)
Time
O(n log n)

Sorting and heap maintenance both stay logarithmic.

Space
O(n)

The heap stores the chosen course durations.
