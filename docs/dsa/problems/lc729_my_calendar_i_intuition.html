First Principles

How to reason about calendar insertion like a sorted shelf

This problem becomes gentle once you stop thinking about “all previous bookings” and start thinking about where the new booking would sit in sorted order.

LC 729Pattern 3Neighbor-only overlap check
Human Version

Every new booking is an online decision

What is fixed?

You cannot reorder old bookings or revisit past answers. Each new interval must be accepted or rejected immediately.

That makes this an online version of interval conflict detection.

Brute Force

The straightforward solution checks against every accepted booking

That is actually a reasonable first version: for each new request, compare it against all earlier bookings and reject it if any overlap appears.

The optimization question is: can we avoid scanning the whole list every time?

Optimization

Sorted order collapses the overlap search to two neighbors

Why only two intervals matter After inserting by start time, only the predecessor and successor can possibly overlap the new interval. Anything farther away is blocked by one of those neighbors already being in between.

That is the entire optimization: use ordered storage so the problem shrinks from “scan everything” to “check adjacent bookings.”

Spot It

Think ordered map when inserts arrive one by one

If the problem is online, interval-based, and only asks whether a new interval conflicts with what is already stored, ordered neighbors are often the right abstraction.
