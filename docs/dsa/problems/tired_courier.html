Original Problem Binary Search on Answer Greedy Hard

Tired Courier

The answer space is continuous, not an array. Binary search the fatigue cap; greedy decides which packages fit in each trip.

Problem

What are we solving?

Problem Statement

A courier must deliver n packages along a road. Package i is at position pos[i] (sorted ascending) and weighs weight[i] kg. The courier starts at position 0, can carry at most k packages per trip, picks them up left to right, delivers them all, then returns to 0. The fatigue of a trip is furthest_position × total_weight_carried. Minimize the total fatigue across all trips.

Example
pos[2, 5, 6, 9, 12]
weight[3, 1, 4, 2, 5]
k (max per trip)2
Output144

Best grouping: trip 1 → pkgs [0,1] → pos=5, weight=4 → fatigue=20  |  trip 2 → pkg [2] → pos=6, weight=4 → fatigue=24  |  trip 3 → pkgs [3,4] → pos=12, weight=7 → fatigue=84. Total = 20+24+84 = 128.

Intuition

The answer is a fatigue cap, not an index

We cannot enumerate all possible groupings — that's exponential. Instead, flip the question: "if no single trip may have fatigue > F, can we deliver everything in valid trips of ≤ k packages?"

If fatigue cap F works, cap F+1 also works. If F fails, F-1 also fails. Perfect monotonic shape for binary search.

Search space: F = 0 … max_pos × sum(weights)  ·  condition: canDeliver(F)

At F=128: all trips can be assigned with ≤ 2 packages each and fatigue ≤ 128. Answer = 128.

The feasibility check (greedy)

For a given cap F: walk through packages left to right. Keep adding to the current trip as long as the trip count ≤ k and the resulting fatigue (next package's position × running weight) stays ≤ F. When either constraint breaks, close the trip and start a new one.

Why greedy works here Packages are fixed in order (contiguous trips). Including more packages in a trip always increases fatigue (both weight and possibly max position increase). So the greedy "extend as far as possible without exceeding F" is always optimal — stopping earlier would only force more trips.

Solution

Binary search on the fatigue cap

public class Solution {

    public long minTotalFatigue(int[] pos, int[] weight, int k) {
        long lo = 0, hi = 0;
        long totalWeight = 0;
        for (int i = 0; i < pos.length; i++) {
            totalWeight += weight[i];
            hi = Math.max(hi, (long) pos[i] * weight[i]); // min single-package fatigue
        }
        hi = (long) pos[pos.length - 1] * totalWeight; // worst case: one trip

        while (lo < hi) {
            long mid = lo + (hi - lo) / 2;
            if (canDeliver(pos, weight, k, mid)) {
                hi = mid;
            } else {
                lo = mid + 1;
            }
        }
        return lo;
    }

    private boolean canDeliver(int[] pos, int[] weight, int k, long maxF) {
        int n = pos.length;
        int i = 0;
        while (i < n) {
            int count = 0;
            long curWeight = 0;
            // Greedily add packages to this trip
            while (i < n && count < k) {
                long newWeight = curWeight + weight[i];
                long fatigue = (long) pos[i] * newWeight;
                if (fatigue > maxF) break; // adding this package exceeds cap
                curWeight = newWeight;
                count++;
                i++;
            }
            if (count == 0) return false; // even 1 package exceeds cap — impossible
        }
        return true;
    }

    public static void main(String[] args) {
        Solution sol = new Solution();
        int[] pos    = {2, 5, 6, 9, 12};
        int[] weight = {3, 1, 4, 2, 5};
        System.out.println(sol.minTotalFatigue(pos, weight, 2)); // 128
    }
}
from typing import List

class Solution:
    def min_total_fatigue(self, pos: List[int], weight: List[int], k: int) -> int:
        n = len(pos)
        lo = 0
        hi = pos[-1] * sum(weight)   # worst case: one trip carries everything

        while lo < hi:
            mid = lo + (hi - lo) // 2
            if self.can_deliver(pos, weight, k, mid):
                hi = mid
            else:
                lo = mid + 1
        return lo

    def can_deliver(self, pos, weight, k, max_f):
        i = 0
        n = len(pos)
        while i < n:
            count, cur_weight = 0, 0
            while i < n and count < k:
                new_weight = cur_weight + weight[i]
                if pos[i] * new_weight > max_f:
                    break           # adding this package exceeds cap
                cur_weight = new_weight
                count += 1
                i += 1
            if count == 0:
                return False       # even 1 package exceeds cap
        return True


if __name__ == "__main__":
    s = Solution()
    print(s.min_total_fatigue([2,5,6,9,12], [3,1,4,2,5], 2))  # 128

Complexity

Time
O(n log(P·W))
P = max position, W = total weight. Each binary search step runs an O(n) greedy scan.
Space
O(1)
Greedy uses only counters and accumulators.
Watch: the lower bound Set lo to the minimum single-package fatigue (min(pos[i] * weight[i])) rather than 0. Any valid solution must be at least that large — a tighter bound reduces binary search iterations.
