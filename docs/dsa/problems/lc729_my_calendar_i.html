My Calendar I

This is online interval checking: bookings arrive one by one, and you must decide immediately whether the new interval can coexist with everything already accepted.

Official LeetCode problem ↗ Build this from first principles ↗
Problem

Accept a booking only if it does not overlap an existing one

Plain-English Statement

You are building a calendar. Each booking request is a half-open interval [start, end).

Implement a calendar that accepts a booking only if it does not overlap any earlier accepted booking.

Original Example
Callsbook(10,20), book(15,25), book(20,30)
Outputtrue, false, true
WhyThe second request overlaps the first, but the third starts exactly when the first one ends.
Intuition

In sorted order, only the nearest neighbors can cause trouble

If bookings are stored in start-time order, then a new interval cannot suddenly overlap something far away without first overlapping its immediate predecessor or successor.

Neighbor-only check Once you know where the new start time would be inserted, you only need to compare against the interval just before it and the one just after it.
Sorted Insert
check predecessor.end and successor.start around new interval
[10,20]
new [20,30]
[35,40]

Nothing earlier than the predecessor can reach past it, and nothing later than the successor can start before it.

Solution

Store bookings in a sorted map and inspect just two neighbors

import java.util.TreeMap;

class MyCalendar {
    private final TreeMap<Integer, Integer> calendar = new TreeMap<>();

    public boolean book(int start, int end) {
        Integer prev = calendar.floorKey(start);
        Integer next = calendar.ceilingKey(start);

        if (prev != null && calendar.get(prev) > start) return false;
        if (next != null && next < end) return false;

        calendar.put(start, end);
        return true;
    }
}
# Python version using a sorted list for the same neighbor idea.
from bisect import bisect_left

class MyCalendar:
    def __init__(self):
        self.books = []

    def book(self, start, end):
        i = bisect_left(self.books, (start, end))

        if i > 0 and self.books[i - 1][1] > start:
            return False
        if i < len(self.books) and self.books[i][0] < end:
            return False

        self.books.insert(i, (start, end))
        return True
Time
O(log n) to O(n)

The ordered-map idea gives logarithmic neighbor lookup, while the list-based Python version pays linear insertion cost.

Space
O(n)

We store every accepted booking.
