Meeting Rooms II

This is the core resource-allocation pattern: all meetings must be served, so the answer is the maximum number active at the same time.

Problem

How many rooms are needed so no meeting is rejected?

Statement

Given meeting intervals intervals[i] = [starti, endi], return the minimum number of conference rooms required.

Input[[0,30],[5,10],[15,20]]
Output2
Intuition

Track when the earliest occupied room becomes free

Unlike LC 435, you are not allowed to throw any interval away. That means we are not choosing a subset anymore. We are simply measuring peak overlap.

Sort meetings by start time. For each new meeting, ask whether the room that frees earliest is already free. If yes, reuse it. If no, you need a brand-new room.

Why a min-heap? The only room you care about is the one that ends soonest. If even that room is still busy, then every other room is also still busy.
MeetingEarliest room endActionRooms in use
[0,30]—Open room 11
[5,10]30Open room 22
[15,20]10Reuse room 22
Solution

Start-order sweep + min-heap of ending meetings

import java.util.*;

class Solution {
    public int minMeetingRooms(int[][] intervals) {
        Arrays.sort(intervals, (a, b) -> Integer.compare(a[0], b[0]));
        PriorityQueue<Integer> heap = new PriorityQueue<>();

        for (int[] interval : intervals) {
            if (!heap.isEmpty() && heap.peek() <= interval[0]) {
                heap.poll();
            }
            heap.offer(interval[1]);
        }
        return heap.size();
    }
}
import heapq

class Solution:
    def minMeetingRooms(self, intervals):
        intervals.sort(key=lambda iv: iv[0])
        heap = []

        for start, end in intervals:
            if heap and heap[0] <= start:
                heapq.heappop(heap)
            heapq.heappush(heap, end)

        return len(heap)
Time
O(n log n)

Sorting plus heap updates.

Space
O(n)

The heap can grow to the maximum overlap.
