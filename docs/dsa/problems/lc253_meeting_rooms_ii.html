Meeting Rooms II

This is the “how many intervals are alive at the same time?” version of scheduling. The answer is not about choosing intervals anymore. It is about counting peak overlap efficiently.

Official LeetCode problem ↗ Build this from first principles ↗
Problem

Find the minimum number of rooms needed to host every meeting

Plain-English Statement

You are given meeting intervals where each interval has a start time and an end time.

Whenever two meetings overlap, they must use different rooms. Return the minimum number of rooms required so that all meetings can happen.

Original Example
Inputintervals = [[0,30],[5,10],[15,20]]
Output2
WhyThe meeting [0,30] overlaps with both later meetings, so one extra room is required.
Intuition

Track which ongoing meeting finishes first

When meetings are processed in start-time order, the only useful room to free is the room whose current meeting ends earliest. If that meeting is already done, its room can be reused; otherwise, a new room is needed.

Why a min-heap fits perfectly At any moment, you only care about the earliest ending active meeting. A min-heap gives you that in one lookup.

The heap stores end times of meetings that are still occupying rooms.

Solution

Sort by start time and maintain a min-heap of end times

import java.util.*;

class Solution {
    public int minMeetingRooms(int[][] intervals) {
        Arrays.sort(intervals, (a, b) -> Integer.compare(a[0], b[0]));
        PriorityQueue<Integer> minHeap = new PriorityQueue<>();

        for (int[] interval : intervals) {
            if (!minHeap.isEmpty() && minHeap.peek() <= interval[0]) {
                minHeap.poll();
            }
            minHeap.offer(interval[1]);
        }

        return minHeap.size();
    }
}
import heapq

class Solution:
    def minMeetingRooms(self, intervals):
        intervals.sort(key=lambda iv: iv[0])
        min_heap = []

        for start, end in intervals:
            if min_heap and min_heap[0] <= start:
                heapq.heappop(min_heap)
            heapq.heappush(min_heap, end)

        return len(min_heap)
Time
O(n log n)

Sorting and heap operations both stay logarithmic.

Space
O(n)

The heap may hold every simultaneously active meeting.
