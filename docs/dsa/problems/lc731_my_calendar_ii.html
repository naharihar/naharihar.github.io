My Calendar II

This is dynamic interval booking with one extra layer: single overlaps are allowed, but the moment a new event would create a triple overlap, it must be rejected.

Official LeetCode problem ↗ Build this from first principles ↗
Problem

Allow double bookings, reject triple bookings

Plain-English Statement

Design a calendar that accepts a new event if adding it still keeps every time point booked at most twice. If any time point would become booked three times, reject the event.

Original Example
Sequencebook(10,20), book(50,60), book(10,40), book(5,15)
Resulttrue, true, true, false
WhyThe fourth booking would create a triple overlap on [10,15).
Intuition

Track both single bookings and double-booked ranges

The clean way to think about this problem is to maintain two collections:

CollectionMeaning
bookedAll accepted events
overlapsRanges that are already booked twice

When a new event arrives, check it against overlaps first. If it intersects any double-booked range, then accepting it would create a triple booking, so reject immediately.

Why this works The overlap list is a compact memory of every place where the calendar is already “full enough.” If the new event touches one of those ranges, you already know it would become the third layer.
Solution

Reject on overlap with any double-booked segment

import java.util.*;

class MyCalendarTwo {
    private List<int[]> booked = new ArrayList<>();
    private List<int[]> overlaps = new ArrayList<>();

    public boolean book(int start, int end) {
        for (int[] range : overlaps) {
            if (start < range[1] && end > range[0]) {
                return false;
            }
        }

        for (int[] event : booked) {
            if (start < event[1] && end > event[0]) {
                overlaps.add(new int[] {Math.max(start, event[0]), Math.min(end, event[1])});
            }
        }

        booked.add(new int[] {start, end});
        return true;
    }
}
class MyCalendarTwo:
    def __init__(self):
        self.booked = []
        self.overlaps = []

    def book(self, start, end):
        for left, right in self.overlaps:
            if start < right and end > left:
                return False

        for left, right in self.booked:
            if start < right and end > left:
                self.overlaps.append((max(start, left), min(end, right)))

        self.booked.append((start, end))
        return True
Time
O(n²)

Each booking may scan existing events and overlaps.

Space
O(n²)

In the worst case, many pairwise overlap segments can be stored.
